# 开 PR、合 PR

## 开之前

- **一块一个 PR，从最新的 master 开。** 一块是交代任务时说的那一件事，比如「暂停和结束」「Codex 接入」。做的时候发现别处也该改，先记在说明的「范围外看到的」里，不顺手做进来。
- 只有下一块确实要用这一块还没合的代码时，才叠在它上面开，并在说明第一行写「叠在 #N 上，要先合 #N」。
- 只提交这一块的文件。不提交密钥、`.secrets/`、`evidence/`、数据库文件、别的会话没提交的改动。
- 提交前跑过 `cognos-deploy` 第 1 步的检查。改了页面或接口的，还要跑过第 6 步。

## 说明怎么写

用中文、平常的话，写给小林看，不写给另一个 AI 看。分四段，每段几行：

```
## 做了什么
（用户能看到或能用的变化，一条一句。不写内部机制的名字，除非小林以后要用到这个词。）

## 验证了什么
（实际跑过的检查和结果。真实叫过 AI 的，写叫了谁、几次。看过截图的，写哪一页。）

## 没验证 / 没做到
（照实写。工程检查通过不等于思考质量变好，也不等于首版验收完成。）

## 范围外看到的
（做的时候发现、但没在这个 PR 里做的事，一条一句，留给小林决定要不要做。）
```

- 版本号改了的，写「app 从 x 到 y，有 / 没有新迁移」。
- 改了桥的启动方式或环境变量（比如 `COGNOS_BRIDGE_COMMANDS`）的，单独写一行。
- 词的选择会带着 AI 走。不用押、顶、碎、站住、重新切，不写百分比，不加〔原〕〔AI〕〔世〕标签。
- 仓库是公开的：不写个人情况，不贴聊天分享链接，不贴密钥或密码。

## 合

- 小林说「可以」才合。别的 AI 说可以不算。
- 叠着的 PR 从最底下那个开始合。每合一个，把上面那个的 base 改成 master 再合。用 merge，不用 squash 或 rebase，不 force push。
- 草稿 PR 先转成正式的再合。
- 合之前确认 head 还是审过的那个提交（别的会话可能还在往上推）。
- 合完：本机仓库切到 master 并 `git pull --ff-only`。本机如果正停在被合的那个分支上，内容一样，可以直接切。切之前先看 `git status`，有没提交的改动就先停下，告诉小林，不要 stash 或丢掉别人的改动。
