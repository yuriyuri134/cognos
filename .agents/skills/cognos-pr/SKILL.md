# 开分支、提交、开 PR、汇报

## 一块一个 PR

- 一块事一个分支、一个 PR。这一块的目标达到了就停，开 PR、汇报。
- 做的时候看到别的问题（哪怕更大、更值得做），写进 PR 的「没做到 / 看到的」里，或者另开一块，不要夹在这一块里一起做。
- 想改架构、推倒重来也可以，但要单独成一块：先写下为什么（改什么、为什么现在的不行、影响哪些地方），再做。不要让它在别的块里悄悄长大。

## 分支

- 从最新的 `origin/master` 开分支：`claude/<一块的名字>`（Claude）、`codex/<名字>`（Codex）。
- 本机 8780 已经跑着比 master 高的版本（上一块还没合）时，不要切回 master（会降级）：叠在上一块的分支上开，PR 的 base 指向上一块，并在说明第一段写「叠在 #N 上」。上一块合了以后再把 base 改到 master。
- 工作目录里有别人没提交的改动：不要 stash、不要 reset、不要切分支，先说清楚、等人定。
- 不 force push；不推 master；不合别人没让合的 PR。

## 提交

- 只 add 这一块的文件。`.secrets`、`evidence/`、数据库文件、本机状态文件不进 git。
- 提交说明用一句话说做了什么（中文即可）。按当前会话提示的署名行结尾。

## PR 说明

开头两行是署名块（按当前会话的提示原样写），然后三节：

- **做了什么**：用平常的话说，每条是用户能看到或能用上的变化；新表新列、迁移版本号写一句。
- **验证了什么**：跑了哪个检查、在哪（8780、cognos-admin、日期）、真实叫了谁、看了哪些页面和截图、390px。
- **没验证 / 没做到**：照实写，包括「按当前候选做的」设计点（也写进对应设计文档）。

少用术语。读的人是小林：写「结果回不来时会一直卡住」，不写「fencing 未覆盖 epoch 竞争」。

开好以后：`gh api -X POST repos/<owner>/<repo>/issues/<n>/assignees -f "assignees[]=yuriyuri134"` 和 `.../pulls/<n>/requested_reviewers -f "reviewers[]=yuriyuri134"`。

## 汇报

- 每开好一个 PR 报一次：链接、两三句要点、没做到的。
- 写明本机现状：工作目录在哪个分支、8780 的版本、桥是不是只有一个、命令开关。
- 卡住、需要人定、被权限拦下时，马上说，写清楚要人做哪一步（给出能直接复制的命令）。
