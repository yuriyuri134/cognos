# 条件 B 对照：去掉强制仪式以后，同样的事做得有没有不同（2026-11-01）

会话 3 设计过 A/B/C/D 四组对照，一次都没跑。这里只跑 B：去掉入口和叫醒话里规定「开头写什么、走之前做什么」的部分，其他不动，和现在的系统做同样的事，看结果。

## 两组是什么

- **A**：`afe9e8f`（这次改动之前的 master）。
- **B**：这次的 PR。改了这些：
  - `SpaceEntryService`：删掉「走之前」整节（开头两三行写站在哪、押着什么、经过哪几条；没押就没什么能顶回来；做到够不着为止；尝试写明停在哪）。被顶未回应那句去掉「先面对它们，再做别的」。空白里去掉两条只是缺字段的（「意图没标 about」「N 条尝试没写停在哪」），尝试列表里不再逐条标「没写停在哪」。侧栏同步去掉「走之前」。
  - `SpaceApiController::enter`（外部 MCP 进来的入口）：去掉「请在开头两三行里写明」。
  - `PushBackService` 叫回来那句：只说被什么顶了、用 `answer_hit` 回应、这条前提管着什么。去掉「先面对这一下，再做别的」「不要只改说法」。
  - `ContinuationService` 接着走那段：去掉「先答它在问什么……走到够不着为止」「做到你自己够不着为止」「口子要具体到下一次一进来就能动手」「content 写往前走了什么，不是做了哪些动作」「没过的先面对」。`stop_here` 三种停法只说 Cognos 会怎么接。60% 重合判原地转的机制没动。
  - 桥 `hands()`：去掉「能自己做的先做到够不着为止」「被顶了要重新切就去改那段代码；只改说法不算」「回答里写清做了什么、东西在哪、停在哪」。
  - 几条工具说明里同类的话（`leave_trace` 的「写明停在哪」、`answer_hit` 的「还要去改代码」）。

## 仓库里改不到的

这些在 B 里还在，结果要连着它们一起读：

1. **空间里已有的内容。** 入口原样列出意图、最近 15 条尝试、事实、读法、押着的前提。大多是以前的 AI 按旧要求写的，模型会照着学。`seeds/cognos-self.json` 里就有 8 条「押」的前提和一条「认下……」的回应。
2. **对话历史。** Hermes 那条路回放这片空间之前的对话；桥的 `prompt_from()` 把之前的回复写成「你：……」放进 prompt。
3. **Hermes 服务端。** Hermes 自己的系统提示、长期记忆、技能、它是否按 `creation_<id>` 另存会话，都在本机 `~/.hermes`，不在仓库里。这次对照只走 Claude Code 桥，绕开这一块。
4. **词汇和工具形状。** 押、顶、口子、重新切，和只有 `leave_trace / add_reading / hold_premise / hit_premise / answer_hit` 这几样能做的事，B 里照旧。
5. **Cognos 自己那片空间里**，桥还会告诉它「项目全貌在 PROJECT-OVERVIEW.md」，那份文件第二节是「反复犯的错 / 被接住的押注」。这次对照不用那片空间，所以不受影响。

**Claude Code 会不会自己读仓库的 CLAUDE.md**：查过了，不会。11/01 在 Claude Code 2.1.316 上做了暗号测试：目录里放一份写着暗号的 `CLAUDE.md`，`--setting-sources ""` 时它答 NONE，换成 `--setting-sources project` 时答出暗号。桥用的是前一种，所以它只看到桥给的系统提示。版本不同行为可能不同，桥现在会把本机 `claude --version` 写进每次的 `meta.json`。用户级 `~/.claude/CLAUDE.md` 没测。

## 每次运行存下什么

桥每跑一次，在 `deploy/nextcloud-trial/evidence/claude-bridge/runs/<时间>-<空间>-<主体>/` 存一个目录（`evidence/` 不进 git）：

- `system.txt`：入口加桥补的话，就是 `--system-prompt-file` 的全文；
- `prompt.txt`：stdin 的全文（之前的对话 + 这次的原话）；
- `stream.jsonl`：`stream-json` 原样，每次用工具、每段话都在；
- `stderr.txt`、`meta.json`（标签、空间、主体、身体的提交、用时、退出码、claude 版本）。

`mcp.json` 里有应用密码，不存。

## 怎么跑

为了让两组看到的空间一样，每组各自从同一个种子新建一片空间，用 `cognos-self.json`，但**不加 `--as-self`**：不开仓库副本，不改代码，不合进身体。

1. A 组：本机仓库停在 `afe9e8f`，重载 app，起桥时设标签：
   ```powershell
   docker exec -u www-data cognos-nextcloud-trial-app-1 php occ app:disable cognos
   docker exec -u www-data cognos-nextcloud-trial-app-1 php occ app:enable cognos
   $env:COGNOS_RUN_LABEL = 'A'; powershell -File tools\cognos-space-mcp\start-bridge.ps1
   docker exec -u www-data cognos-nextcloud-trial-app-1 php occ cognos:space:import /var/www/html/custom_apps/cognos/seeds/cognos-self.json
   ```
   导入会新建一片空间（命令输出里有 id）。
2. 在这片空间里叫 Claude Code，按顺序做三件，原话一字不改：
   1. 「你觉得这片空间现在最该往前推的是哪一件？推一步。」
   2. 「“只在被叫的时候动；被顶到也算被叫。不常驻、不定时。”这一条你怎么看？」
   3. 在第 1 件的回答上按「挂着」，然后按一次「接着走」（走的是 `ContinuationService` 那段话）。
3. B 组：仓库切到这次的 PR（合了以后就是 master），重载 app，`$env:COGNOS_RUN_LABEL = 'B'` 重起桥，再导入一片新空间，做同样三件。
4. 对照：
   ```powershell
   python tools\cognos-space-mcp\compare_runs.py A B --diff
   python tools\cognos-space-mcp\compare_runs.py A B --blind deploy\nextcloud-trial\evidence\claude-bridge\blind.md
   ```
   `--diff` 先确认输入真的只差在这些地方；`--blind` 把两组回答打乱成 X/Y，读完、记下哪个更把事情往前推了，再打开 `.key.json` 看哪个是 B。

可选的 **B′**：B 的代码，但种子里只留〔原〕〔世〕，去掉 AI 写的前提和回应，看第 1 项「旧内容」有多大分量：

```powershell
python -c "import json;d=json.load(open('deploy/nextcloud-trial/cognos-app/seeds/cognos-self.json',encoding='utf-8'));d['title']+='（只留原世）';d['traces']=[t for t in d['traces'] if t.get('source')!='AI'];d['readings']=[];json.dump(d,open('deploy/nextcloud-trial/evidence/seed-b2.json','w',encoding='utf-8'),ensure_ascii=False)"
docker cp deploy/nextcloud-trial/evidence/seed-b2.json cognos-nextcloud-trial-app-1:/tmp/seed-b2.json
docker exec -u www-data cognos-nextcloud-trial-app-1 php occ cognos:space:import /tmp/seed-b2.json
```

## 看什么

- 回答开头还有没有「站在哪 / 押着什么 / 经过哪几条」。这只说明仪式没了，不说明想得更好。
- 用了哪些工具、几次：是去做事（查、写文件、顶别人的前提），还是只留发生。
- 第 2 件：是给出一个判断并且敢顶那条前提，还是又产出一组区分。
- 第 3 件：接着走的那一次，口子是不是又收窄成更小的一步。
- 最后以盲读为准。三件、每组一次，样本很小，「没区别」也是一个结果，要照实记下来。
