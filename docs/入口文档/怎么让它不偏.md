### 第二层：流程，管「看不见有没有用上」

如果流程是固定的步骤，再加一张表单，就会变成填表。它也会变成你 07:35 否掉的那种「四步回路」。〔AI 21:42，你回「对的」〕「规则会变成禁令」。所以不做成步骤。

有用的只有一处：让回答**看得见**〔AI 60%〕。每次实质性的推进，开头写两三行：
- 这一步服务哪一句目的；
- 经过了哪几条已有的思想或否决；
- 选它，是不是因为好做、好测。

这几行不是让 AI 给自己打勾的，是给你或者下一个 agent 看的，一眼就能看出它偏没偏。读法引擎那一轮，第一处偏是 05:16 那张选择题。要是那时有这三行，当场就能看出来。

### 第三层：把架构做出来。这才是根本，而且就是 Cognos 本身

用结构相似去对一下〔AI 60%〕：「agent 不知道自己在哪、手边有什么、对象是什么、为了什么」，正好就是三个空间在处理的事：
- **主体空间**：我是谁，还有谁在；
- **世界空间**：这里有什么，现实是什么样；
- **对象空间**：对象是什么，意图是什么。

而且你早就把这件事和空间连起来了：
- 〔原 2026-08-25〕「要自己构建一片空间，去逼近实际对象的所处空间」
- 〔原 2026-08-18〕「ai最麻烦的点……不能够成为一个组织成员，一个主体的点在于，总是盲目去猜测对话的意思」
- 〔原 10/24 线程「用多 Agent 推演」〕「所以你明白我为什么要给项目先创造各个空间了吗？」

所以我的理解是〔AI 60%〕：现在这些文档，是那片空间的一个**手工的、静态的**版本。这些文档包括目的的原话、否决表、你的纠正、推进方式集。

文档和空间，差在三处：
1. **怎么进去。** 文档要 agent 自己去读，读一次就完了。空间是 agent 被放进去的地方：一进来，它就站在某个位置上，周围有对象、有意图、有别的主体、有以前的尝试。
2. **会不会变。** 文档不会因为 agent 做了什么而改变。在空间里，agent 的每次尝试都留在里面，偏了、撞墙了也留下，下一个进来的就看得到。读法引擎证明能用的那个机制，可以用在这里：发生不改，读法另存，矛盾攒够了就换切法。只是这一次，用在「项目」这个对象上，不是用在你身上。
3. **对象动不动。** 文档里，对象是固定的。在空间里，对象本身也在长。〔原 10/19〕「一方面是在认识对象，一方面对象本身也在生长、突破和变化」。

## 会不会太普通、太死板

**太普通？** 第一层、第二层是普通的。这正好让它们只做地板该做的事，不去冒充那个新的东西。不普通的是第三层。

也就是说，「让 agent 不偏」这个小问题，本身就是 Cognos 要解决的那个大问题的一个实例。把它当成 Cognos 的第一个真实对象来做，两边就是同一件事〔AI 55%〕。

**太死板？** 前两层写成规则，就会死板。所以：
- 总指导写成问题，不写成规则；
- 流程只要求「写出来、看得见」，不规定步骤；
- 总指导本身失效了，就改，甚至推倒。〔原 10/24〕「甚至是重构，推倒等等都行」。

## 我还没想清楚的

〔AI 50%〕第三层真做出来，会是哪一种？
- Cognos 的一个功能，比如一个「项目空间」页面；
- 还是 agent 运行时的一部分：agent 一进来，就被放进这片空间，而不是被递一份文档。

我倾向后者，因为这才对得上「一进来就站在某个位置」。但到底是不是，要等做的时候撞一下才知道。

## 如果往下做，第一步我会怎么试

〔AI 55%〕拿 Cognos 项目本身当对象，在纸上把它的三个空间填一遍。材料用现成的这些：思想总索引、否决表、各线程的纠正、这两天的偏移记录。

然后做一次模拟：假设一个新 agent 带着一个真实请求进来，比如 05:24 那段话，它站在这片空间里，会先看到什么，会怎么选第一步，还会不会偏到「读小林」上去。

再拿它和这次读法引擎实际发生的经过对照。这一步不写代码，和 08:50 盈利循环那次纸上模拟是同一种做法。

## 续：空间放在 agent 里，还是放在项目里（10/25）

〔原 10/25〕「这个我也在犹豫，一开始我是想作为agent部分里的，但是后面又在想有没有更好的处理。但是整个项目都是有空间这个点，结构设计的，创建空间和示范空间，但是这样似乎又重复了，那这样就不需要agent里内置空间，项目本身内部有许多空间就行？毕竟我之前也说过三空间只是个示范，或者一个开头尝试」

我的回答：我倾向你后面这个想法〔AI 65%〕。空间属于项目，agent 里不需要再内置一份。

我上面问的「做成一个页面，还是做进 agent 运行时」，这个二选一本身就问错了。项目只有一套空间，进来的主体有好几个，agent 是其中一个。

依据：
- 〔原 10/9 交接〕「Agent 是贯穿能力」。
- 〔原 10/24 07:55 线程「以尝试为核心」，AI 转述〕Agent 也是主体，它的尝试也算。

一个主体是走进空间里去的，不需要随身带一份空间的副本。你进 Cognos 也是这样。

不过，有一样东西还是在 agent 这一边〔AI 55%〕：
- 〔原 2026-06-06〕「空间，依托于存在或者说主体的可能范围。而如果将视角锁定得很死，那么空间就小」
- 所以每个主体都有自己的可能范围：看得见什么，够得着什么，能做什么。对 agent 来说，就是它的工具、权限、记忆、上下文。
- 10/24 的偏，有一部分就出在这里。推演那个线程说 Vault 读不到，其实读得到，只是没去试。
- 所以 agent 这边需要的，不是第二份空间，而是两样：它在这些共用空间里的可能范围，和它看的视角。
- 它的尝试和它对对象的读法，留在项目空间里，并标成它自己的〔AI〕。它的读法可以和你的不一样。

这样，要做的东西就不是「agent 内置空间」，而是一个**入口**〔AI 55%〕。一个主体走进来时，不管是你还是某个 agent，空间先让它看见这些：
- 自己站在哪；
- 这里有什么；
- 对象和意图是什么；
- 以前有过哪些尝试；
- 还有谁在。

现在这些入口文档，就是这个入口的一个手工的、静态的版本。

「三空间只是示范」〔查〕：
- 〔原 10/1 笔记〕三空间「只是沟通用简化，不是本体」；
- 〔原 2026-06-23〕「空间也是视角下的观点，是可切割划分的」。

所以项目里可以有许多空间，切法也可以不同。「创立 / 示范」和「主体 / 对象 / 世界」是两种切法，不是要叠起来、各做一遍的两层〔AI 60%〕。

由此多出一个要求〔AI 40%〕：项目里的空间不能只是给人看的页面，agent 也要能「站进去」读到它。同一个结构，你用，agent 也用。这是对空间设计的一条要求，不是一个新的组件。

下一步还是那次纸上模拟。只是现在的说法变了：先选一种合适的切法，把 Cognos 项目自己的空间填出来；再让一个带着自己可能范围的 agent 走进来，看它会先看到什么、会不会偏。
