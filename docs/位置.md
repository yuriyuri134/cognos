# 位置：每次押着什么，和上次比挪了多少

〔AI 10/28〕开这份的原因：每次会话都从总指导重新开始，回答「我站在哪」，但从来不用回答「我上次站在哪，现在挪了多少」。原地转圈只能靠小林的感觉发现：〔原 10/27 10:35〕「感觉你每次推进都太小了」，〔原 10/27 23:07〕「往往会停下来，或者思考并没有推进，只是原地踏步」。这份把它摆出来。

## 一、怎么用

规则在 `PROJECT-OVERVIEW.md` 〇节第 7 问下面，这里只说怎么写：

- 会话开头，从本文第三节找同一条线的最后一行，在给小林的第一条回复里写「位置·上次：……」。没有就写「没有记录」。
- 会话结尾，写「位置·这次：押着……，结果：站住 / 碎了 / 重新切 / 这次在转圈」，同时在第三节追加一行，随这次的 PR 提交。不开 PR 的，写在最后一条回复里，下一次有 PR 的会话补进来。
- 「结果」只能是小林的回应或现实碰回来的东西给的，不是自己评自己。还没有回应的写「等着」。
- 两行一样，或者这次押的只是换了说法，就写「这次在转圈」。转圈不是错，没写出来才是。

〔AI 10/28，55%〕这份最可能碎在：写成套话。每行都写「押着 X，结果：等着」，看起来在记，其实没人去对。所以第三节每行都要写出处（PR、文档、哪句原话），能对得上。

这份本身撞着一条：〔原 10/27 10:31〕「你改变的最多可能只是个强调吧」。加第 7 问和这两行，又是给 AI 多一段要读的文字，大半还是强调〔AI 60%〕。我押它不只是强调的那一小半在这里：这份记录是小林能直接看、能拿来顶 AI 的东西，转圈从「感觉」变成一行行能对的字。如果一周后这里只有套话，或者没人往里写，这一押就碎了。

## 二、线

一条线就是一个大方向。新开一条线，在这里加一行。

- **框架**：Cognos 的框架和架构往哪动，AI 怎么在这里思考。
- **盈利循环**：创立空间里的第一个对象。
