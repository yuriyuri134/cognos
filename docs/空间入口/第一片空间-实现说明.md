## 一、这次做什么，不做什么

**做**，只在创立空间里，做一片空间的三样东西：
1. **留下**：发生过的东西，进了空间就不改。
2. **入口**：谁进来，都先看到自己站在哪。
3. **读法**：某个主体对发生的理解，和发生分开放。

**不做**：
- 不做「主体 / 对象 / 世界」三个固定栏目。〔原 10/1 笔记〕三空间只是沟通用的简化。
- 不做任何进来之前要先做的事：不填表，不选模式，不先建空间。〔原 10/20〕「为什么？删掉」
- 不做候选菜单。〔原 9/7〕「不是展开候选，是尝试」
- 不做自主心跳。只有被叫的时候，或者有人打开页面的时候，才动。
- 不做模拟器、可视化、再组织。这些是下一步，等用的时候露出缺口再做。

## 二、数据：两张表

### `cognos_space_traces`：发生，只增不改

| 列 | 说明 |
|---|---|
| `id` | |
| `space_type`, `space_id` | 这次只有 `creation` 加创立 id。留着这两列，是为了以后空间套空间 |
| `kind` | 自由文本，不是枚举。种子里会用到：`intent` 意图、`fact` 事实、`attempt` 尝试、`feedback` 现实碰回来的、`material` 材料、`correction` 更正 |
| `source` | `原` / `世` / `AI` |
| `author` | 谁留下的：用户 id，或者参与者名（Hermes、claude.ai 线程……） |
| `content` | 正文。原话照原样放，不改写 |
| `said_at` | 这件事发生、或者这句话被说出来的时间。可以早于入库时间，没有就空 |
| `act` | 这句话当时在做什么：定义、类比、举例、提问、顺口一提、陈述。不知道就空 |
| `confidence` | 只有 `source = AI` 的才填，0–100 |
| `status` | `said` 说过 / `confirmed` 确认 / `rejected` 被否 / `withdrawn` 撤回。默认 `said` |
| `about` | 自由文本：它和哪个意图、哪个对象有关。可以空，空就是「不知道」 |
| `stopped_at` | 只给尝试用：停在哪里、为什么停 |
| `touched_reality` | 只给尝试用：碰过现实为 1，只在模型上推（模拟）为 0 |
| `ref_id` | 更正、确认、撤回指向的那一条 |
| `created_at` | 入库时间 |

规则：
- 不提供改和删。
- 要改 `status`，就新写一条 `kind = correction`，用 `ref_id` 指过去。原来那条的状态，读的时候按最新的更正来算。
- 这样「被否」「撤回」本身也留在历史里。

〔AI 45%〕和 8/12 否决的张力：这张表看上去像固定 schema。区分在于，它只给每条痕迹标来路，不规定空间里有哪些东西。所以 `kind` 和 `about` 都是自由文本。

### `cognos_space_readings`：读法

| 列 | 说明 |
|---|---|
| `id`, `space_type`, `space_id` | |
| `reader` | 谁的读法 |
| `content` | 读法正文 |
| `confidence` | AI 的才填 |
| `refs` | JSON 数组，指向它读的那些 trace id |
| `superseded_by` | 被同一个 reader 的新读法替换时填上。旧的不删 |
| `created_at` | |

不同主体的读法可以并存、互相矛盾，都留着。〔原 10/24〕「他的尝试也可能和我是不一样的，甚至方向相差甚远，但也是一种」

## 三、入口：`SpaceEntryService`

`render(spaceType, spaceId, subject, callMessage)` 返回一段文字。
- Hermes 被叫进来时，这段文字放进 system prompt。它替换 PR #4 删掉角色以后剩下的那一句「这里是 Cognos 的创立空间」。
- 页面侧栏显示同样的内容（第五节）。同一个结构，人用，agent 也用。

内容，按下面的顺序拼。顺序只是为了排版，不是步骤：

1. **你在哪**
   - 这里是 Cognos 的创立空间「标题」。
   - 它在 Cognos 里面。Cognos 为了什么：放两三句原话，从配置文件 `appinfo/purpose.md` 读，不写死在代码里。先放这三句：
     - 〔原 06-18〕「我想让ai学会真正的思考，或者像我一样能够思考」
     - 〔原 06-26〕「让一切的尝试真正地尝试了，而不是被忽略，或者避开」
     - 〔原 10/23〕「想创造一个东西，让这个东西协助我和ai，协助我们思考，完成任务，组织调度」
   - 这次是谁叫的，原话是什么。
2. **还有谁在**：在这片空间留过痕迹的每个主体，各自最近留下的一条。
3. **意图**
   - 所有 `kind = intent` 的，原文照放，带来源、时间、状态。
   - 被否的、撤回的也列出来，标明状态，并排在后面。
   - 多个意图分开列，不合并。
4. **以前的尝试**
   - 按时间列，每条带：谁做的、停在哪里、碰没碰过现实。
   - 太多时，只取最近 15 条，并注明「还有 N 条」。
5. **事实和现实碰回来的**
   - `fact` 和 `feedback` 都带时间。
   - `said_at` 超过 30 天的，标「可能已经变了」。（纸上模拟里，「每天 6–8 小时」就是这么过期的。）
6. **读法**：每个 reader 最新的一条，标是谁、几分把握。
7. **空白**：算出来以后照实写。不编，也不补成建议。
   - 哪些意图下面一条尝试都没有；
   - 哪些意图下面的尝试，全都没碰过现实；
   - 有没有说不清的地方。`act = 提问` 且没有后续的原话，就算一处。
8. **你能做什么**：这次能用的工具；够不着的东西（例如「你看不到小林电脑上的文件」）。
9. **走之前**：这片空间请每个进来的主体做的事，人和 agent 一样：
   - 开头两三行写清楚：你站在哪；你读到的意图是什么，经过了上面哪几条；这一步是不是因为好做才选的。
   - 你做的尝试，用 `leave_trace` 留下，写明停在哪、碰没碰现实。
   - 你对这里的理解变了，用 `add_reading` 留下。

〔AI 55%〕第 9 条要说明白。它不是把刚删掉的角色换个说法塞回来。角色说的是「你是谁，该怎么表现」；第 9 条说的是「这片空间请每个进来的主体留下什么」，小林进来时侧栏里也显同样的话。如果小林觉得它还是角色，就删掉。

## 四、Hermes 在创立空间里能用的工具

现在创立空间调用 Hermes 时没有带工具〔查，`executeWithUnderstanding` 里 `callHermes(..., null, 'hermes-agent')`〕。Activity 那边已经有工具机制。这次给创立空间接上：
- 已有的 `search_notes`；
- 新的 `leave_trace(kind, content, about?, stopped_at?, touched_reality?, act?, confidence)`
  - `source` 固定写 `AI`，`author` 写参与者名。
  - Hermes 不能写 `原` 和 `世`。
- 新的 `add_reading(content, refs, confidence)`
- 新的 `search_traces(query)`：在这片空间的痕迹里找。

**同时删掉创立空间的 `understand()` 关卡**〔查，`chatCreation`〕。现在每条消息都要先被分类成 question / suggestion / reflection / critique / expansion 五类。置信度低于 70，就回一句「我理解你的意图是：**提问**，置信度…能帮我确认一下吗？」。这有两个问题：
- 它是一道关卡，和 10/20 删掉的「先建空间」是一类东西；
- 它用一个五选一的分类，代替了对意图的理解。

〔AI 65%〕这一条超出了 PR #4 的范围，单独列出来，请小林确认。

## 五、页面：创立空间侧栏「这里」

- 位置：`creation-detail` 右侧，可折叠。默认展开。宽屏和对话区并排，窄屏收成抽屉。
- 内容：第三节的 1 到 7 条，和 Hermes 拿到的是同一份。
- 每条痕迹显示：来源标记〔原〕〔世〕〔AI〕、时间、状态。尝试另外显示停在哪、碰没碰现实。
- 小林能做的四件事，都是一键或一个小框，都不是关卡：
  1. 对某条点「确认」或「不对」，写一条 correction；
  2. 加一条〔世〕：现实碰回来的；
  3. 把自己的某条消息标成「意图」或「事实」，新写一条 trace，`source = 原`，正文照抄；
  4. 看「你上次来之后多了什么」：按用户记一个 `last_seen`，侧栏顶上列出之后新增的痕迹和读法。
- 风格：深色主题，沿用现有 token。界面参考成熟产品的侧栏（Linear、Notion 的详情侧栏）。

## 九、接入 Claude Code（小林 10/25 07:37 问：「可以接入cladue code进去吗？」）

可以，有两种接法。我建议两种都走同一个接口〔AI 60%〕。

**接口**：空间对外开四个动作，做成 Nextcloud 的 OCS 接口，再包一层很小的 MCP server。
- `enter(space, subject, message)`：返回第三节那段入口文字；
- `leave_trace`；
- `add_reading`；
- `search_traces`。

谁走进来，用的都是这四个，Hermes、Claude Code、Codex 都一样。这就是「同一个结构，你用，agent 也用」。

**接法 A：Claude Code 从外面走进这片空间。** 先做这个。
- 小林本机的 Claude Code 配上这个 MCP server，就能 `enter` 盈利循环这片空间。
- 它在里面做的尝试，以 `author = Claude Code` 留下。下一个进来的，不管是 Hermes 还是小林，都看得到。
- 这也把开发这边和产品这边接上了（入口初稿第四节第 7 条）：开发 Cognos 的 Claude Code，也可以从 Cognos 自己的入口进来，而不只靠 `CLAUDE.md`。

**接法 B：在 Cognos 里叫 Claude Code，和叫 Hermes 一样。**
- 有先例〔查，commit 3a73f71〕：读法引擎已经能用 `READING_LLM_BACKEND=claude-cli` 走 `claude -p`。
- 做法：
  - 在 Windows 主机上起一个很小的桥接服务，收到请求就调 `claude -p`。系统提示要写成文件再传，因为 `claude.cmd` 遇到换行会丢掉后面的参数。
  - Nextcloud 容器经 `host.docker.internal` 调这个服务。
  - 在 `cognos_participants` 里加一个参与者「Claude Code」。
- 代价：走的是小林 Claude Pro 的额度，额度用完就叫不动了；每次调用还要冷启动一个 CLI，比 Hermes 慢。
- 所以 B 等 A 用顺了再做。
