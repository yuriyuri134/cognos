## 一、给 AI 的阅读顺序

1. [`PROJECT-OVERVIEW.md`](../PROJECT-OVERVIEW.md) 〇到二节：总指导七问和开头结尾的「位置」两行、为了什么（只有小林原话）、AI 在这里反复犯的错和被接住的押注。
2. [`思想总索引.md`](思想总索引.md) 〇节（每次都要经过的）和第四节（撞过的地方：碎在哪、还剩什么能用）。提方案前对一遍。
3. [`位置.md`](位置.md)：同一条线上次押着什么、结果如何。会话开头抄最后一行，结尾追加一行。
4. [`现状-2026-10-28.md`](现状-2026-10-28.md)：做了什么、谁在做什么、卡在哪。
5. 按手上的事挑：
   - 框架往哪走 → [`框架审视/`](框架审视/)（最新，10/27–28）
   - 空间、入口、创立空间的代码设计 → [`空间入口/`](空间入口/)
   - 展开、尝试、三个空间 → [`空间与展开/`](空间与展开/README.md)
   - 怎么推进、AI 为什么偏 → [`推进方式/`](推进方式/)、[`入口文档/`](入口文档/)
   - 想法怎么记、记在哪 → [`记录与经过-机制.md`](记录与经过-机制.md)
6. 动代码前，再看 `PROJECT-OVERVIEW.md` 的「代码与运行」「开发方式」，和 [`空间入口/第一片空间-实现说明.md`](空间入口/第一片空间-实现说明.md)。`AGENTS.md` 里让先读的施工台账和行动思想是 9 月 FastAPI 原型时期的，可以当来路看，不是现行产品的规格。

## 二、怎么改这里的东西（给其他 AI）

- 在分支上改，开 PR，由小林合。不要直接推 master。
- 每句标来源，标记跟着句子走：〔原 日期〕小林原话，〔AI xx%〕AI 推测，〔世 出处〕现实里碰回来的，〔查〕查过记录。小林的原话不改；要更正，用删除线加一句更正说明。
- 新加文件，就在本文对应的表里登记一行。改了项目现状，改 `PROJECT-OVERVIEW.md`，不要另写一份总览。
- 不放密钥、口令，不放个人生活和联系方式。
