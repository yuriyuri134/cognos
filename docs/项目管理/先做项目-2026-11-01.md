## 二、模型的问题：不是只能接 Claude Code

〔查〕Cognos 现在叫模型有两条路，都在你电脑上：
- **Hermes**（WSL，`8642`），模型走 a6api 中转。
- **Claude Code 桥**（`tools/cognos-space-mcp/claude_bridge.py`），在你电脑上跑 `claude -p`，用的是你的 Claude Pro 订阅（#6 起会把 `ANTHROPIC_API_KEY` 之类的变量剥掉，确保走订阅）。

所以：
1. **Cognos 跑在 Nextcloud 上，是你自己的程序，想叫哪个模型都行**：a6api 中转的、Anthropic API 的、别家的。它不绑定 Claude Code。
2. **「这里的模型」和 Claude Code 里的是同一家模型。** 你在这里喜欢的，主要不是模型本身，是外面那层：协调者、线程、清单、记忆、PR 一变就把 AI 叫醒〔AI 75%〕。这层要在 Cognos 里自己做，换哪个模型都要做。
3. **钱怎么算**：Pro 订阅包了 claude.ai 和 Claude Code（额度两边共用）；走 Anthropic API 是另外按量计费，不在订阅里。桥走订阅，所以不额外花钱，但会吃你在这里用的同一份额度。
4. **反过来是可以的，正着不行**：这个 claude.ai 项目里的 Claude 不能被 Cognos 当成接口去叫（它没有给外部程序调用的口子）。但这里的线程可以走进 Cognos：在你电脑上开 Remote Control，或者经 `tools/cognos-space-mcp/` 进空间，10/25 就这么做过。云端线程够不着你本机的 8780，除非开公网隧道。

## 三、先做项目，还是先做组织：我押先做项目〔AI 65%〕

经过的：〔原 10/27 23:07〕「我一边在想是不是要先把组织部分做出来，参考claude tag那样」；`docs/框架审视/为什么会停-2026-10-27.md` 第五节〔AI 65%〕：照 Claude 这套做组织界面解决不了停，**值得做的是组织下面那一层**：谁押着什么还没完、什么会把它叫醒、什么会真的顶回来；还有 10/27 那份「参考 Claude 项目，重新想 Cognos 的项目」，〔原 10/27 09:07〕「可以」的几条：尝试按线程切、走开时事情还在走、回来能看清。

我现在的读法：**那「下面那一层」就是项目管理。** 组织管的是谁和谁在一起说话；项目管的是什么还开着、下一步欠在谁那、什么一变就该叫醒谁。AI 会停、会原地踏步，问题出在后一层，所以后一层先做，组织以后长在它上面（一个项目里走动的那些主体，就是组织的第一批成员）。

今天就有一个现成的证据〔查〕：你说「几个线程内的会话，和项目进度有些忘了」。这个 Claude 项目没法让你一眼看到「什么开着、欠在谁那」，我是从记忆文件加 GitHub 现查拼出上面那张表的。这正是 Cognos 的项目部分该补上的。

### 具体押什么

- **第一个项目是 Cognos 自己**，内容就是上面那 6 个 PR 和它们背后的线程。每一条是一个「没完」：押着什么、停在哪、下一步欠在谁那（大多数欠在你：合不合）、什么会叫醒它（PR 有动静、你回一句、检查跑完）。
