**项目的形成，应当增加持续工作的能力。** 一段想法、会话或尝试可以先存在于 Initium 中继续展开；确立项目时，为这件事建立稳定入口、当前理解、有关材料与工作安排，并表达可投入的参与者、范围和资源，这些内容允许逐步补足。

同一段活动可以成为多个项目的来路；原会话继续按会话查看，项目引用促成它的段落，后续可补充范围、拆出分支或让分支独立，已有链接仍能回到原文及当时位置。

**项目内部同时支持探索与落实。** 首页按小林的选择显示项目名字及独立小项目，进入项目后能看到当前理解、下属部分、正在开展的尝试、具体工作安排、已有成果以及重要变化；参与者可以从另一条线进入，项目页面组织可随工作需要调整。

一个尚未想清的问题可以展开几种方案；一项尝试可以包含一段对话、多次推演或现实活动，已有具体交付时再安排任务、依赖、负责人和结果要求，阶段总结保留每次认识如何变化。

**多处关联要记录各处怎样使用同一份内容。** 会话或文件有稳定身份与版本，项目中的关联说明相关段落、用途和采用的判断；项目当前采用的安排另有来源与修订历史，因而同一材料可以同时支持不同的工作。

若「项目形成」分支改变了对入口的判断，其他工作依据其引用的具体内容检查影响；内容相似可以提示关联，建立同一工作、合并或替代的关系需要可查的依据，存在分歧时各方方案仍可继续。

| 需要稳定留下的东西 | 第一版承载的内容 |
|---|---|
| 来源 | 原始提供方、会话或文件身份、消息或段落位置、版本、取得时间、已取得范围；模型整理和原文各有身份，附件缺失可见。 |
| 项目及位置 | 名字、当前说明、参与者、下属部分、关联来源、位置沿革；一项内容可被多处使用。 |
| 尝试与工作 | 正在处理什么、当前读法或方案、已有结果、执行承诺与依赖、何时值得再面对。 |
| 方案及采用记录 | 作者、依据、受影响部分、当前采用情况、替代关系和修改版本。 |
| 运行及结果 | 谁因为什么开始、基于哪个版本、所用资料、实际结果、交回情况、失败和恢复状态。 |

这是一组用于实现和讨论的工作安排；遇到目前形式表达不了的活动，可以先以独立内容和明确关联承载，再根据反复出现的操作需要扩展形式。

**自主推进必须同时回答方向、权限和持续运行三个问题。** 项目负责人可以把一段研究或实现交给 AI，明确关注的问题、可使用的资料与工具、工作范围、资源和需要回报的变化；范围内 AI 可以自己选择切入点、扩展研究、执行和调整，实质结果直接回到相关工作，授权变化另行记录。

旧稿「每次由人确认」统一改为按范围委托，旧稿「默认生效」具体落实为授权范围内的可追溯更新；一位 AI 对结论的采用仍保留作者和依据，项目范围、资源或对外承诺发生变化时按该项目已有的决策方式处理。

项目接到新消息、有关资料发生变化、依赖工作返回结果，或者参与者已经承诺继续处理时，都可以形成运行机会；排队前先检查依赖、权限、资源、暂停状态和实际运行能力，再让负责判断的参与者选择值得处理的方向，并保留可改选的理由。

运行只在存在可继续的工作且条件具备时延续；没有新信息、缺少外部条件、资源用完或已达成目的时，留下成果、暂停原因和重新开始的条件，进展评价关注问题与工作实际如何改变。

常驻服务负责等待触发、恢复未完成运行和交回结果，模型调用用于需要判断或开展工作的部分；一次事件或结果重复到达要能识别，暂停后排队与重试也遵循暂停状态，并行结果回流时核对起步版本及已发生的修改。

第一版就要保存运行身份、原始请求、领取状态、输入版本和待交回结果，利用当前 Activity 已有 request_id 去重与状态更新经验完善这条链，具体存储和锁的实现留到实施设计核对。

**上下文和项目界面从同一批工作事实出发。** 人能看正在推进什么、有哪些可进入的位置、哪些结果需要面对；AI 根据本次请求先获得当前工作及必要依据，再沿项目内外关系取材，其取材和最终写入可回查。

历史回看、纯理论推演、重新理解问题、暂停某条路线，都可以成为有理由的工作，所谓前沿可以同时有多个位置；相似文本、动作数量、连续运行时长和代码测试通过分别提供有限线索，进展要回到这次工作的对象与成果判断。

Claude 聊天端、GPT 聊天端、Claude Code、Codex 都按独立参与者考虑，各端能力由实际连接提供，共用项目资料和工作结果，同时保留各自的会话身份与来源。

| 接入设计必须核对的能力 | 验收得到什么 |
|---|---|
| 读取项目与按需查原文 | 能看到取得范围、缺少的材料、引用位置及版本。 |
| 在授权范围操作项目 | 能创建活动、写入自己的方案与成果、更新被委托的工作，并区分作者。 |
| 会话原文与附件取得 | 分别核对原文、选摘、模型整理和附件；连接工具的能力逐项验证。 |
| 运行与接续 | 分别核对能否被叫起、能否恢复原会话、能否自行回报、失败后怎样恢复；允许从新会话重新进入同一项工作。 |

当前仓库已提供 Hermes 和本机 Claude Code 调用路径，以及 stdio MCP 空间工具；四个客户端的端到端项目协作、账户可用权限、自动原文同步尚待按真实连接确认。（来源：[工具服务](https://github.com/yuriyuri134/cognos/blob/b9d39b0f8ce02dbfd47a46e40f84cd4511707b8b/tools/cognos-space-mcp/server.py)、[现行桥](https://github.com/yuriyuri134/cognos/blob/b9d39b0f8ce02dbfd47a46e40f84cd4511707b8b/tools/cognos-space-mcp/claude_bridge.py)、[模型服务](https://github.com/yuriyuri134/cognos/blob/b9d39b0f8ce02dbfd47a46e40f84cd4511707b8b/deploy/nextcloud-trial/cognos-app/lib/Service/HermesAgentService.php)，本轮静态核对范围）

**已有机制按它所承担的工作重新安置。** Initium 继续承载开始与展开，确立增加持续工作的组织和委托，项目页展示多个可继续的位置；未完事项参与选方向，纠正定位到具体判断及受影响工作，守望接收有关变化，消化既支持当场留结果，也支持后来读入既有会话。

“项目是推进的主体”保留为设计假设，落实为明确的目标、参与者、判断与运行能力；项目与尝试之间可以建立形成关系；笔记、学习、组织可以逐步共用资料、参与者和运行服务，它们各自的产品形态继续按实际需求设计。

“默认往大推”调整为按问题选择尺度，具有后续用途的理论展开、重新界定问题和重新组织材料都可成立；Initium 的改名是已知选择，名称对模型倾向的效果仍需具体观察。

**复用与重构的边界按当前代码安排。** Nextcloud 登录与文件、Deck 的卡片执行能力、Activity 的原始来源快照与消息历史、已有参与者路由、Claude Code 执行和输入日志都是复用起点；项目多处关联、当前采用状态、方向判断和可靠续接需要新增或重构。

本轮规划的建设顺序如下，每段都交付可完整使用的能力；实现期间再按依赖切分提交。

1. **项目能形成、展开并实际工作。** Initium 与直接会话入口、名字总览、项目及分支、来源关联、尝试简介和阶段历史、探索与执行安排、AI 工作和结果回流一并进入第一版；基础版本校验、暂停、运行身份与可靠回流随首个自主执行路径一起完成。
2. **多个参与者能持续共同推进。** 扩展四类客户端的已验证接入，完善方向选择、并行方案、依赖和影响传播、角色委托与恢复，让已经接通的端能够沿同一项工作接续。
3. **结构能随工作改变。** 完善分支独立、合并、跨项目成果、多处采用与历史位置回指；根据实际工作进一步扩展视图、操作和其他形态。

第一版的设计验收要面对同一件工作发生变化的全过程。下面是待验证场景，本轮只完成静态审查与方案推导。

| 场景 | 必须能观察到的行为 |
|---|---|
| 从尚未确立的对话长成项目 | 原文及早期活动继续可找，项目增加组织和后续工作能力，另一项工作也能引用同一来源。 |
| 一段会话涉及两个分支 | 两处各自说明用途，修改一处采用的判断后，相关位置能检查具体影响。 |
| 人离开后继续研究 | 授权范围内完成值得推进的工作，有实际结果，遇到条件限制时能停下并说明，回来可从另一位置切入。 |
| 中途纠正、两个参与者同时更新 | 纠正指向具体对象，并行结果对照各自依据版本，旧方案与新方案的来路可查。 |
| 桥退出或结果回调失败 | 能找到运行及已产生结果，恢复交回只生效一次，已有外部执行结果先核对。 |
| 理论探索暂时没有代码产物 | 能保留问题展开、反例、方案比较及认识变化，下一位参与者能据此继续判断。 |
| 后续决定拆分、合并或停止 | 旧链接、采用关系与运行历史仍可定位，等待与暂停状态正确约束后续执行。 |

本轮已能选择产品结构和运行方向，接下来的设计重点是把“哪一项工作值得继续”与“哪些变化已经影响项目”各自深入到真实情形，随后核对数据与接口的实现范围。
