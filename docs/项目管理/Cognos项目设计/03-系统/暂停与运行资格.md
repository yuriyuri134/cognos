# 暂停、结束与再开：执行边界

当前实现：0.29.5（2026-11-04），接续 #39/#41，交付在草稿 #42。依据：01-产品/开始与重组.md 与 04-交付/阶段与验证.md 的 V08。本文合并此前逐版本记录；旧稿保留在 Git 历史。

## 当前行为

项目有 active、paused、ended、exploring 四种状态。paused 保留安排等恢复，ended 结束本轮投入，exploring 停下原安排并容许另起自由探索。项目、位置、讨论、采用、来路和旧链接都保留。与 merged_into 分开表达。

非 active 不派新的项目工作；人仍可读、讨论、改稿和记决定。已有运行可能仍在外部执行，结果照收，不能宣称进程已停止或外部副作用已撤销。普通消息已保存但未叫 AI 时，界面明确说明。

退回探索的项目出现在 Initium，可查看原项目和位置，再以新原话另起独立会话。原会话不搬动，新会话通过根位置 usage 关联回原项目，Initium 显示反向来路。新会话不复制旧讨论、不继承旧委托，也不自动注入原项目全部上下文。它可沿 Initium 流程让 AI 先试或确立；原项目需明确 resume。

独立出的项目继承来源的四种状态及最近的再开条件，初始 revision/epoch 为 1；原运行不能把直接写入资格迁过去。新项目历史写明“系统记录”，不冒充用户新决定。合并遵循目标项目状态，预览明确来源/目标状态、旧运行结果照收而直接写资格不迁移。源项目身份和原位置链接保留。

## 接口、存储与并发约束

- POST /projects/{id}/lifecycle：action=pause/end/explore/resume、expected_revision、request_id，可选 note/reopen_when。切换到不同状态，revision 与 epoch 同增；同状态新请求返回 409，旧 request_id 重放回原回执。已合并源项目不接受独立的状态变更。
- cognos_projects 保存 state/lifecycle_revision/execution_epoch；cognos_lifecycle_history 保存项目+revision、前后状态、actor、原话说明、再开条件、时间。总览读取最近 100 次历史。继承状态的系统说明标明其来源性质。
- GET initium/data 包含 exploring；POST /projects/{id}/explorations 接 text/request_id，在项目锁内核 exploring、创建原话会话并关联。恢复后旧探索窗口返回 409。
- RunService::create 在事务中锁项目，核 active，登记运行 project_id/epoch；非项目会话独立。旧运行不回填新资格。网络派发在事务外。
- AI 改稿和直接采用在写事务内重新核 active、项目身份和 epoch；恢复不会续旧资格。失效稿留作比较，采用留提议，人可明确处理。
- 生命周期、运行登记、改稿、AI 采用、新增位置和重组共享项目锁。重组按相关项目 ID 排序加锁，等待后重读归属和计划。运行登记/改稿/AI 采用在等待后重查位置归属，变化时拒绝旧入口。预览依据含项目状态与 epoch。
- HermesAgentService 在选择会话 AI 之前核准入，Claude 桥再经过事务登记；直调 Hermes 尚无完整桥式持久运行回执，不能把准入门等同完整接入。

## 派发与结果边界

桥连接异常、响应丢失、非明确拒绝回复进入 unknown；明确 400/401/403/409/422 为 failed，202 为 running。未知工作不自动重复派发，迟到结果仍可接收；迟到传输错误不能覆盖 delivered。

委托随关联运行区分未知和未接下；派发回执只更新仍为 starting 的委托，避免覆盖先到的 returned。ProjectInactiveException 与桥 BUSY 区分，即使两者都是 HTTP 409，也不能混用“停止派发”和“忙时排队”。

结果按 result_id 只存一次。当前结果提交后的差异记录、委托回执和自动接续仍有故障窗口：不能因此宣称完整 V08 已完成。下一段需把数据库内收尾纳入同一事务，再为外部后续动作设计可恢复、不会盲目重放的投递。
