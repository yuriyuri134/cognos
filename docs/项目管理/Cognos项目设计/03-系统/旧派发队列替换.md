# 持久派发队列：当前实现与后续

当前实现 0.30.6（2026-11-04），交付在草稿 #42。此前分阶段稿见 Git 历史。

## 解决的问题

旧 PushBack 队列通过 IConfig JSON 数组读改写，可能并发覆盖；drain 先出队再派发，失败时丢掉选择依据。现在实际消息与反对派发使用持久队列，先领取、再原子关联 run、最后网络派发。桥对空闲后重复 run_id 尚无独立幂等回执缓存，所以未知请求不能靠重发实现 exactly-once。

## 当前路径

- cognos_queue_scopes 按空间锁定和分配顺序；cognos_dispatch_queue 保留 msg/hit 原引用、顺序、状态、followup/run 关联、稳定导入身份、说明和时间。不复制原内容或 AI 摘要。
- queued→claimed→sent；明确忙拒绝可回 queued，其他明确拒绝 skipped；领取失联或派发不明 unknown，不自动重排。sent 不代表模型判断正确或工作质量达标。
- 同一未完原因去重；已完成后明确新入队另留尝试。前插语义保持。领取与结算认 followup 身份，claimed/unknown 阻挡自动越过。
- enqueue/drain 及后台恢复主动扫描旧配置，按旧数组顺序导入整数 hit 和字符串 msg，保留原值；稳定 legacy_key 防止复活旧项。创建会话类型的旧项在同一事务导入并暂挂 held，不因发现旧数据重新授予执行资格。held 阻挡自动领取且在页面可见/可取消。明确继续的再授权入口尚未实现。
- RunService::create 在同一事务绑定队列项，核空间、原引用和领取者，并写入不可变 input_snapshot；校验失败回滚新 run。msg 绑定 conversation 的 reply_to，hit 绑定 hit target。
- 接受、失败、未知、租约到期与结果回流同步对应队列；更新认当前 run_id，旧回执不覆盖新尝试。忙拒绝清当前资格，旧运行输入保留原领取来源；通用 settle 不得修改已绑定运行的队列项。
- PushBackService::afterHit 先入队，再按原顺序有条件领取本条；已有工作/未知项时排队。drain 同时处理 msg 和 hit，失效反对可 skipped；未知不取下一件。即时 hit 与忙时 hit 共用队列。
- FollowupDispatcher 将领取信息传入消息重调；明确 busy 将接续意图退回 pending，异常保留 unknown，暂停取消旧接续资格。队列 claimed 过期转 unknown，永不因过期重排。
- 用户核清并关闭未知 followup 时，其关联 unknown 队列同步记 reconciled；不重放，也不改变实际 run。独立即时 hit 及其余队列现可在项目页直接核对：全部 queued/claimed/unknown 与最近十条已处理记录可见，显示原讨论、引用与对应运行状态。queued 可取消，unknown 可留说明关闭；校验原讨论所有权与预期状态，带 request_id 回执。若关联未知 followup，同事务一起核清；两个入口统一先锁 followup 再锁队列。不会修改实际 run。

## 实际验证发现的内容问题

真实忙时排队最初两次回应都能到，但第二次调用按用户消息 ID 截断，漏掉了后来完成的前一条回答。模型只能猜前一判断是什么。这不是加一条“不要猜”的提示能解决的。

现在排队回复允许纳入对更早用户消息已经完成的回答，即使回答 ID 晚于当前排队消息；仍排除后续新用户请求。普通手动 recall 保留原截断语义。替身检查核到实际发送的 history，真实运行的不可变 input_snapshot 也核到前一实际回答。只证明输入完整性改善，不推断整体思考质量上升。

反对路径检查还发现旧双引号 sprintf 的位置参数被 PHP 变量插值，在派发前报错，已修正转义并重验。

## 仍待推进

1. 旧积压已能主动扫描与保留迁移证据（cognos_queue_imports：源键、源 hash、状态、数量、说明、检查时间），后台任务实际执行通过。当前仅创建会话类型主动导入；无法识别/定位的来源保留原值并记状态。明确继续的再授权和持久唤醒还待接上；不能把找回记录当成已经恢复执行。两个关闭入口的真正并发交错仍需专项验证。
2. 真实 hit 叫回、暂停/恢复、进程断电与外部动作核对。当前替身 hit 检查不能替代真实 AI hit 场景。
3. 运行级 fencing、桥 run_id 幂等及所有并发交错；人工核清不等同外部进程已经停止。
4. 显式 recall 的新尝试和 HTTP 重试进一步绑定请求身份；已有消息/trace 引用去重不应冒充所有请求已幂等。
5. 继续原规划的重组撤回、工作拆分、Codex 接入、尝试简介与阶段总结；多账号和备份恢复仍在验收范围。
