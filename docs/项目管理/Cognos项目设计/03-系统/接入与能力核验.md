# 四类客户端接入与能力核验

[总纲](../README.md) · [上下文](../02-协作/上下文与历史.md) · [接口](接口与一致性.md) · [运行](../02-协作/自主推进与可靠运行.md)

Claude 聊天端、GPT 聊天端、Claude Code、Codex 是已记录的接入要求 R07。它们共用持久工作及来源，不要求使用相同模型、提示词或会话机制。每个实际连接单独报告能力，不能由“支持 MCP”推导出完整会话、附件同步和主动唤醒均已具备。（来源：R07/S07 §17）

## 能力必须分别核验

| 能力 | 核验动作 | 成功凭据 |
|---|---|---|
| 项目读取 | 从指定项目取一个现状和一个原文段落 | 真实对象 ID、版本、选区与缺口。 |
| 项目操作 | 在授权位置写独立方案，按版本修改受委托工作 | change_id、作者、权限和页面回读。 |
| 会话取得 | 取得一段带分叉和附件的既有会话 | 消息身份、覆盖范围、分叉与附件实际内容。 |
| 增量同步 | 新增消息后再次取得，模拟编辑与重复导入 | 无漏消息、无错误覆盖，缺口和新版本可见。 |
| 工具执行 | 执行一项已有授权的真实工作 | operation_id、回执、成果、验证与结果回流。 |
| 主动调用 | Cognos 向该端派发一次工作并收到返回 | 触发、领取、运行和交回记录。 |
| 原会话恢复 | 以已有 runtime 继续，并面对最新纠正 | runtime ID、当前状态回读和实际回应。 |
| 新会话接手 | 不依赖旧 runtime，在新会话继续同一工作 | 独立读取记录及对工作有用的新增结果。 |

## 适配器与结果契约

适配器描述 participant_binding、capabilities、支持的读取/写入/执行/唤起/恢复方式、可用状态、最近核验时间及凭据。工作请求带稳定 work_id、run_id、snapshot_id、授权引用和回报目的地；返回统一的成果/回执结构，保留平台原始会话/运行标识。

凭据留在适配器配置与受保护存储，不进入上下文快照、文档或事件正文。Cognos 工具只授予该参与者当前允许的操作；平台连接能力和项目委托共同约束执行。

原生聊天端不能被主动调用时，可由人在该端打开当前工作包，端内读取和回报；完整原文取得不了时允许授权导入或选摘，并标范围。这个降级路径支持共同工作，但状态应写“人工发起/选摘”，不能写“自动同步”。

## 首版与扩展

首版至少一端完成读现状→查原文→写方案/执行→可靠回流→新会话接手，同时保留其他端的导入/读取入口。完整四端是后续逐项兑现的需求；每端成功一项就更新矩阵中的那一项，不整行宣布完成。（D06）

接入文档仅给能力契约，不提供当前服务支持状况的推测。实施时通过实际可用插件/官方接口和账户环境核验；若需要产品使用说明，再按当时官方材料查证。
