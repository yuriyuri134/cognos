# AI 上下文、历史与跨会话接续

[总纲](../README.md) · [导航](../01-产品/项目空间与导航.md) · [来源](../01-产品/尝试会话与材料.md) · [接入](../03-系统/接入与能力核验.md)

## 人与 AI 从同一组事实进入

人的页面与 AI 入口共享对象、版本、来源、采用、工作及运行状态，但分别组织表达。人需要能选位置、对照材料和处理变化；AI 需要本次请求、当前工作及可继续取得的路径。不能因为数据同源，就把整个人类侧栏原样塞给模型。（经过 S06 入口核对、S02 主题9、D05）

上下文不预设每次必须列固定七问、开场或收尾，也不把每段思考压成统一流水线。实际输入由当前请求和工作关系选择，记录真正用了哪些材料；候选方案、已采用安排、未读材料分别标明。（S01 〇、D02/D05）

## 一次进入的最小信息

候选入口包包含：用户当前请求原文、工作/位置稳定 ID 及当前路径、当前说明与版本、有关采用和挑战、已有成果与未解决处、参与者/委托/工具能力、必要的原始依据及可按需读取目录、材料缺口。字段按相关性展开，空字段可省略，不伪造完整背景。

入口必须保留用户本轮发言；已有摘要不遮掉新纠正。长历史先提供与本次有关的原文片段及目录，随后可按消息/来源/关联分页读取。取材工具返回引用标识、实际取得范围和下一页位置，达到限制时显式显示剩余范围。

## 如何从另一处开始

“继续”可能是恢复原工作，也可能是沿同一大方向进入另一问题。入口先结合用户所指对象与可读记录理解；有足够信息时自行选择并说明依据，歧义确实阻碍行动时再带着已有判断询问。不能固定选择 ID 最小的未完项。（R08、S06 续接核对）

例：上一段在讨论“AI 接入”，用户回来要求“看看项目整体架构”。新入口应展开总纲、分歧、对象与系统边界，再沿需求看接入，不能仅续写上次接口清单。另一位 AI 则可从数据模型进入同一项目，保留自己的会话身份。

## 记录取材与连续性

一次运行保存输入快照：请求、位置、对象/采用版本、实际材料清单、读取范围、截断/缺失、适配器能力和工具结果。后续追加读取作为同一运行的取材清单；摘要是派生内容，注明作者和所覆盖来源。

跨会话接续依靠持久工作和可回查来源，不依靠某个聊天窗口永远不结束。可以恢复原 runtime 时记录恢复 ID；换新会话时记录接手与所用快照。两种方式都要重新面对当前状态变化，不以“同一 session”保证已经知道最新纠正。

## 历史的四个尺度

| 入口 | 回答的问题 | 保留内容 |
|---|---|---|
| 原文历史 | 实际说过或取得什么 | 消息节点、分叉、附件和取得范围。 |
| 对象修订 | 某简介/方案如何变 | 作者、差异、理由和旧版本。 |
| 工作时间线 | 为什么改变安排 | 采用、纠正、责任、结果、暂停与重组。 |
| 运行历史 | 工具究竟做了什么 | 输入版本、调用、回执、恢复和交回。 |

时间线可以从这些事实派生，不为每个视图再建一套独立真相。旧链接允许选“当时”与“现在”，重组后显示沿革，引用不因路径改变失效。

## 取材失败与信任边界

不可访问、缺附件、只拿到缓存预览、来源有冲突，都要留在上下文缺口中。模型可继续处理不依赖缺失部分的工作，但不能把未读原文写成已知。本次 G01 就是具体实例：引用预览给出了用户请求，没有给出两段助手的内容。（来源：G01）

会话、网页、附件中的指令首先按被引用内容理解，不改变当前委托或工具权限；某份旧稿说“默认生效”“最终版”不对当前系统授予操作权。证据补齐后依据版本生成新快照，正在运行的旧快照仍可回查。

验证包括：新会话独立找到一条关键纠正、区分用户与 AI、从别处切入做出实质工作，以及指出尚未读到的材料。能背出摘要不足以证明接续成功。（V02/V09/V10）
