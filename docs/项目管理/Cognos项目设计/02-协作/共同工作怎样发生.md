# 共同工作怎样发生

[总纲](../README.md) · [判断与采用](判断采用与纠正.md) · [自主推进](自主推进与可靠运行.md) · [模型](../03-系统/数据模型.md) · [接入](../03-系统/接入与能力核验.md)

2026-11-03 修订：经过 GPT 的通读评审（S12）、Gemini Argon 的四点工程评审（S13），以及小林接受局部重构并要求更新、提交、接手实现的回复（R14）。保留原文、用途、采用、运行的区分和 Claude 已交付的可靠回流；重写人和 AI 如何实际一起工作的衔接。这里是产品行为，不是要求模型每次复述的思考格式。

## 一、回来时有一件可以接着改变的东西

项目名字进入一个工作位置。这里可以是一段正在写的设计、一组互相竞争的解释、一个研究问题，也可以是一件执行工作。当前内容可以很短、可以为空；它不是进入会话或开始探索的前提。人在结构、历史或材料处进入，都能开启新的方向。

页面把当前内容、有关会话和材料、变化经过放在一起。AI 的一篇回答先是有作者的产出，保存后可以继续修订、与另一个版本比较，或接入当前内容；不同方案保留，不因采用其中一个就删除另一个。会话中的原句仍有自己的身份。当前工作稿、用户原话决定和项目正式采用的安排是不同的状态，不因都显示在一页就混为一项。

这使“推进”有一个实际落点：接手者能看见正在处理什么、已有成果、哪些仍未解决，并能在原来的成果上修改；不必从最后一条消息开始，也不必先把研究编成任务清单。尝试的简介和阶段总结由工作需要产生，不要求每轮对话都生成总结。

## 二、自然的话怎样引起变化

一条消息保留原作者、转贴者、时间、指向的消息或方案版本。参与者可以为它建立用途、提出解释和关联；解释记在解释者名下，并引用原句，不能把 AI 推出来的意思署名给用户。保存来源和推断来源分别可查。

改变共享内容时，系统同时看：这句话在请求什么、回答的是哪个对象及版本、已有委托覆盖哪些操作、现在要改哪些范围。关键词不独立决定权限。例如：

| 当时发生的事 | 可以产生什么变化 |
|---|---|
| 对“继续讨论还是实现”回答“继续” | 结合被回答的问题理解；无法确定是否授权实现时，先继续不依赖该权限的讨论。 |
| 对明确版本的方案说“可以，按这个做” | 在所指范围内采用并执行；记录原消息、方案版本及范围，不变成全局长期授权。 |
| 已委托维护某处设计，AI 发现具体修正 | 按当前权限和版本直接提交，留下 AI 作者和依据；不用每次再等一句“可以”。 |
| 转来另一个 AI 的评审 | 保存该 AI 的观点和小林的转贴关系；是否采用由当前请求及已有委托判断。 |
| 用户纠正 AI 对原话的理解 | 留下纠正，修订解释及受影响安排，原话和旧解释仍可回读。 |

只有超出当前授权、影响范围不明而又必须作决定时才询问。提案本身不冒充决定，但 AI 在委托内的行动也不被永久限制为“只能提案”。目标和授权的变更遵从用户实际委托；质疑目标不等于获得修改目标的权限。

“在生效的决定”独立保存用户原话、原消息引用、适用范围、生效/撤回及替代关系。AI 可代为登记，登记者和原作者分别记录；不需要先造一条 claim 再假装用户采用自己的话。进入某处时优先给出适用的当前决定，并能展开原文与经过；无关决定不堆成每次都要读的规则墙。

旧会话导入时先核作者、时间、取得范围和后来的替代记录。可以由明确证据确定仍有效的，不因“导入”而一律重新确认；证据不足则标有效性未核，保留原句。不会建立要求小林逐条批准的积压列表。

## 三、没有形成任务的探索也能运行

运行可以挂在会话、尝试、位置、工作项或 Initium 条目上，用 target_type/target_id 标识。它可以只有一句“看看这里还能怎么想”，无需预先给出假设、验收答案或“发现 X 就改变 Y”。purpose 记录当时在意什么，未知就如实保留；权限及资源边界由委托给出。

运行中能换问题、开新方向、补材料、比较解释、推进已有成果、提议重组，也可以有理由地等待。问题重构和理论成果都能成为实际进展。方向判断参考相关的困难、价值、用户关切、可触及的现实和投入，不要求固定候选数、评分或固定结尾。

输入快照和起步位置不可改写。发现结果服务另一处时，新增服务关系和可追溯的归属变化；接收结果与应用结果分开。对目标位置的写入仍校验当前权限和版本，改挂不能扩大原委托。

反复无变化、新结果与前提冲突、用户关切转移等是回头检查的线索，不能仅凭文字相似、固定轮数或问题没改名就判定无效探索。资源到限按明确约定暂停，保留成果和未决；下一步可以重新审视问题本身，而非机械选择列表第一项。

## 四、读到、引用、依据和约束分别处理

| 关系 | 证据 | 变化后怎样处理 |
|---|---|---|
| 进入过输入 / 已取回 | 输入快照或工具读取回执，带实际取得的版本和范围 | 下次进入相关工作时提示有新版本；不主动叫醒所有读过它的人。输入出现不证明模型理解。 |
| 引用 | 产出中的来源指向，可由系统提取并保留取得方式 | 在成果旁给更新线索；引用本身不证明结论依赖它。 |
| 依据 | 产出/采用的 basis_refs、参与者可选提交的 depends_on，或业务操作明确使用的版本 | 相关未完工作进入复核；不是所有引用一律重算。 |
| 约束 | 当前适用的决定、采用与授权范围，由系统查得 | 即使运行未读到、未上报依赖，也要在执行和应用结果前核对。 |

depends_on 是补充证据，不是模型完整内因的证明。未填表示“没有上报”，不等于不存在依赖；不因为缺它就拒绝保存一项成果，也不强迫模型增加固定汇报段落。既有只存空数组的运行不能补造“没有依赖”的结论。

主动提示主要来自：有关的新决定、依据被纠正、受委托工作完成/卡住，以及必须处理的权限或版本冲突。读过的文件一般更新只在下次进入时提示。可疑影响先保留可追查线索，逐步用实际漏报/误报调整，不宣称已能精确推导全部语义依赖。

## 五、结果回来后，怎样进入共同工作

先可靠保存产出和实际执行回执，再比较起步时与当前的来源、决定、权限及工作版本。没有相关冲突且在委托内的变化可直接应用；存在分歧时保留成果和双方版本，指出需处理的差异，不覆盖新工作。授权被撤回也应接收旧运行成果，但不再执行越界的共享写入。

结果投递成功、内容被采用、外部动作成功、验证通过分别可见。模型说“完成”不会替代工具回执；交回的研究方案也不需要制造外部代码产物才算有价值。将一段回答接入当前稿时，保存原消息引用和操作者，避免把 AI 原文变成用户原话。

## 六、变化走到每个参与者的哪些环节

| 可观察事件 | 能说什么 | 不能据此推出什么 |
|---|---|---|
| saved | 变化已提交 | 其他人已收到 |
| delivered | 目标接收端确认收到 | 已进入下一次输入 |
| included | 某次输入含该变化的指定版本 | 已阅读、理解或同意 |
| responded | 参与者回应采用、质疑、不适用或暂缓，附回应引用 | 已实际修改或验证完成 |
| applied / verified | 具体变更已提交 / 具体结果已验证，附回执 | 所有参与者都理解了 |

这些是带证据的事件，不是强制人人逐级填写的进度条。时间先后和 depends_on 单独都不足以证明“照着做”。页面显示已核实的状态和未获知的部分，不显示“所有人已知道”。

对叫不醒或无法观测的网页会话，显示“尚无接收/回应证据”，不能断言它不知道。提供可复制的带版本入口和重新取材路径；回流时比较输入依据及当前约束。用户可能暂时还需搬一次，但系统不能因此谎称双向同步已接通。四端的读取、完整会话取得、主动唤起、恢复和回写分别实测（见接入页）。

## 七、共用能力与实施接续

运行、委托、回流、影响和重新判断作为空间层的共用能力；项目是完整使用它们的一个形态，Initium、笔记或学习不必先伪装成项目。Q09 保留解释层面的讨论，当前实施按这个边界推进（R14）。

首个可用版仍是 P1+P2。跨会话接着做、交出去走开回来、几方同时工作三个真实来回共同验证价值。Claude 的 PR #28 已交付运行留存和桥的可靠交回基础，不能据此宣称完整 V08/V12 已通过。

下一段接通“项目名字 → 工作位置 → 当前内容/历史/材料 → 在此对话 → 结果回来”：复用现有会话和运行服务，位置有自己持续的讨论入口，引用别处会话不会移动或改写其身份。再继续在生效的决定、按范围委托、采用与纠正、Initium 形成和重组。完整范围和本轮覆盖见[阶段与验证](../04-交付/阶段与验证.md)、[维护与覆盖](../04-交付/维护与覆盖.md)。
