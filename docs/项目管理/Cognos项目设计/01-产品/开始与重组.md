# 自由开始、确立与重新组织

[总纲](../README.md) · [对象](产品与对象.md) · [事务契约](../03-系统/接口与一致性.md)

## 没有项目时已经可以做事

「我突然想到，一开始项目是不存在的」；随后可以先记录想法或开始会话，再确立项目。（小林 2026-11-01 经 S03 转引，R05/R06）

Initium 用作这一入口的名称，采用 R09 的改名选择。它可以容纳记录、会话、材料和已经展开的尝试；不要求先填项目目标、分支或正式分类。每份内容保留作者、时间及来源，已有活动可继续进行。是否需要独立 Initium 数据实体仍是实现选择：当前候选是自由活动的聚合视图及形成关系，而非必须先建一种“苗”。（来源：R09，D10）

创建 Initium 条目时一句话或一个链接就能留下。“原来的问题、当时怎么推、限制、未验证的路、当时那股劲”是回顾旧探索是否仍可继续的参考视角，有什么留什么，不作五个必填字段或固定五段模板。

直接建项目也成立；从笔记、组织会话或外部材料开始时，不必搬到 Initium 才能确立。系统可提示有关材料或尚未取得的附件，但相似内容不能自动视为同一工作。（D01/D09）

## 确立项目的操作

用户在一段会话中谈了两件事，只想把其中一件持续做下去。操作先指向那段话，允许加入其他有关消息、笔记或已有尝试；创建名字和当前初步说明，并决定哪些工作继续在项目中开展。完整原会话仍可展开，其另一话题仍可单独继续。（承接 S04 的纸面场景）

候选提交包含来源选区、名字、初步说明、建立者、时间及形成理由。参与者、预算、目标和安排可以后补；但若同时开启 AI 持续工作，必须已经有足以支撑该工作的委托与资源边界。项目创建和运行启动各有结果，创建成功不谎称执行已启动。（D03/D08）

确立不改变原文身份；记录 `formed_from` 关系，将原活动和项目链接起来。一次活动可以促成多个项目，多个活动也可共同促成一个项目。项目说明是新构造的当前描述，不能取代最初的话。

## 重组动作

| 动作 | 发生什么 | 必须交代的后果 |
|---|---|---|
| 调整位置 | 改某位置的主导航父项或排序 | 对象 ID 不变，保留旧路径和新路径，不形成导航环。 |
| 追加关联 | 同一内容在另一位置使用 | 新建使用关系，说明用途、范围、读哪个版本，不移动原文。 |
| 分支独立 | 为一条方向建立独立项目与责任安排 | 原位置 ID 可作为新项目根位置继续使用，记录旧项目的历史归属和去向。 |
| 项目合并 | 选择目标项目，将源项目的入口与工作按明确方案整合 | 源身份保留为已合并，列出未解决的采用、权限、承诺和运行差异。 |
| 工作拆分 | 把一个范围分为多个可独立维护的工作 | 新工作各有来源和范围，旧对象保留拆分映射，不把一份外部承诺无声复制两次。 |
| 退回自由探索 | 撤掉当前项目投入安排，在 Initium 等处继续 | 保留项目身份与经过，明确哪些委托暂停、哪些仍有效。（源于 S05 §12 假设） |
| 暂停或结束 | 项目或尝试不再按原安排推进 | 说明未完成内容和再开条件，撤销或暂停相应运行资格。 |

“合并项目”不自动合并两个相反判断。可以共同保存两个方案、采用其中一个、限定各自适用范围，或暂时并存；需要由具备相应权限的参与者作出具体选择。（D04）

## 执行重组前后

系统先给预览：受影响位置、引用、采用、负责人、访问范围、等待项及运行。用户或被授权者确认具体变更后，以预期版本提交一个原子变更；无权限或版本失配时整批失败并保留预览。

运行中的工作保留起步位置与输入快照；回流到稳定工作 ID，另显示当前归属。重组撤销了授权时先接收并保存结果，不自动应用共享状态。把旧项目内容放入访问更宽的目标时，不自动扩散原材料权限；必要时只显示可访问引用或请求具体授权。（D03/D08）

重组撤回以新变更恢复适当关系，不回滚掉重组后他人的成果。若撤回时已有新工作，先形成新的差异预览。首版支持单个调整、独立和明确目标的合并；批量复杂重组与跨组织授权后置，行为契约保持一致。（D06）

验证重点是旧链接仍找得到内容及当时位置、多处采用保持原有含义、在跑的结果不丢失或误写，见 V05/V08。


## 实现状态补记（2026-11-04，0.31.0）

位置页和项目总览的移动经过可点「预览撤回这次调整」。确认后以新变更把当前位置和当前子树移回原上级；稿件版本、讨论、采用和后来新增的子项保留。原变更和撤回互相可追溯，同一请求重复提交返回同一结果。后来归属已变化、出现导航环、原上级不可访问或预览失效时不执行。

独立、合并的自动撤回尚未接入，工作拆分也仍在原定范围。0.31.0 起的新重组会在同一事务里保存前后项目、位置和决定范围快照，为后续撤回提供依据；旧记录缺失的范围不补猜，快照也不作为覆盖后来稿件和用户决定的备份。


## 独立、合并的撤回（2026-11-04，0.31.1）

有完整前后关系记录的新重组，可从位置或项目的经过里点「预览撤回这次重组」。撤回独立把当前独立项目接回原上级，独立项目身份保留并指向归回位置；独立后新增的全项目决定缩到归回部分，不扩大到其他位置。撤回合并把当前子树接回原项目身份，恢复原有决定范围，但不复活后来已撤回、被替代的决定。后来仅管这部分的决定随内容归回，目标项目自己的全项目决定留下。预览列明这些决定，在主内容区展开并取得键盘焦点，避免挤在结构导航窄栏。

当前稿、讨论、采用、委托和后来新增的子项保留；原位置链接、原重组和新的撤回记录都保留。原有的一部分后来又被拆走、原上级/归属变化，或生效决定同时管到归回部分与留在目标的部分时，不自动替人决定范围，须先处理冲突再重新预览。缺少旧快照的重组继续可用普通独立/合并按现状组织，不推测原范围。

接收位置的项目更新运行资格，包括普通合并：此前在目标项目登记的运行仍可交回结果，继续直接改稿或采用须重新登记。这是当前按项目统一维护资格的明确边界，防止位置移出去又回来时旧运行恢复权限；并非中止外部进程，也不撤回已有成果。撤回合并保持原项目现有推进状态，暂停不会因为曾合入活跃项目而自动再开。

登记、替代、撤回决定与重组共用项目锁。决定变化使旧重组预览失效；重组改变了决定归属，等待中的旧决定操作也不会写进已经过时的项目。


## 工作拆分落位（2026-11-04，0.32.0）

现在可在位置里登记有明确范围的执行工作，记录负责人、交付、验收、结果依据与版本，再预览拆成数份。原工作保留为拆分来源，子项引用其具体一版；原委托和结果不复制，子项各自明确安排。完成与运行返回分开记录。实际行为、资格与未完成项见[工作项与拆分](../03-系统/工作项与拆分.md)。
