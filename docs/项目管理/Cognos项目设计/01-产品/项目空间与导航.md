# 项目空间与导航

[总纲](../README.md) · [对象](产品与对象.md) · [上下文](../02-协作/上下文与历史.md)

## 项目总览

项目空间总览以项目名字为主要内容，区分大项目及暂未归入的小项目；不将进度、待办、统计塞进名字列表。这承接已有明确选择，证据层次见 R02。查找、建立项目和进入 Initium 的操作可以放在页面工具区，不改变列表本身的简洁用途。（来源：R02）

项目名并不要求全局唯一，链接用稳定 ID。重名时可在搜索候选中显示归属和少量上下文，用户选定后仍以名字导航。归档项目可按需展开；另一个项目引用它时仍能直接到达。

## 进入具体项目以后

候选布局：左侧是主导航位置树；中间是当前位置的可编辑说明、正在处理的工作及内容入口；对话可在当前页展开；需要追溯时展开来源和历史。较窄屏幕切换结构/工作/对话视图，保持当前对象与未发出的草稿。（D05；布局待真实页面验证）

| 页面区域 | 用户能回答的问题 | 主要操作 |
|---|---|---|
| 当前位置与当前说明 | 我在哪，这里目前处理什么 | 编辑说明、查看依据和历史。 |
| 下属部分与关联位置 | 还能去哪里，哪些内容从别处使用 | 进入、关联、重组，查看此处使用理由。 |
| 在生效的决定 | 小林说过、现在对所有参与者都有效的是哪几条 | 查看原话和日期；只有小林能撤销或改写。 |
| 当前工作 | 谁在做什么、还有哪些值得开展 | 进入尝试、接手工作、查看等待条件和新方向。 |
| 会话与材料 | 这里的讨论和成果来自哪里 | 开对话、引用已有段落、展开原文及附件范围。 |
| 方案及待面对项 | 哪些判断采用了、哪些被挑战 | 比较版本、采用、处理纠正、说明暂不处理理由。 |
| 成果与经过 | 实际获得了什么、为什么改变 | 查看结果、运行回执、阶段总结与时间线。 |

「谁在做什么」按参与者列出：人和每个 AI 端此刻正在动哪个对象、基于哪个版本。两位参与者要改同一个对象时，后来的一位进入前就能看到前一位在动它。11/03 上午几个 AI 同时改同一批文档、互相不知道，靠小林转述，这一栏就是为这种情况设的。（R13；V12）

项目首页和分支页使用相同操作原则，内容按其范围组织。总项目对话可以处理跨分支安排，分支对话围绕局部工作；它们引用同一来源时保留各自用途。前沿视图聚合多个可继续的位置，不能让“最后一条未完事项”覆盖全部可进入方向。（R03/R08、D05）

## 进入与继续的具体路径

1. 从名字进入：显示当前说明与可进入位置，允许直接提新问题。
2. 从搜索结果进入：打开命中的对象和原文段落，保留它在当前项目怎样被用到的上下文；不强行跳回项目首页。
3. 从旧链接进入：说明链接指向当时的位置，给出当前去向；内容、原来归属和重组记录可分别查看。
4. 从完成结果进入：先看结果及它服务的工作，展开开始时依据，选择继续原尝试或另开方向。
5. 从另一位置进入：沿大方向选择新的问题或分支，能查看先前相关工作，无须伪装成恢复最后一轮对话。（R08）

## 空页面、状态和错误

新项目只有名字也能进入，说明和工作安排逐步补充；空分支提供“讨论”“加入材料”“开展尝试”等直接动作。保存失败保留草稿；发现并发版本时显示双方差异；引用目标不可访问时给出访问状态，不泄露未授权标题或正文。

“AI 正在研究”展示实际运行身份与状态；“结果未交回”“等待外部条件”“需要你决定”各有不同入口。页面只在取得真实回执后表示操作完成，避免把模型一句“已更新”当作页面状态。（D08）

首版默认布局可以固定，位置说明和工作排序可编辑；复杂布局编辑器后置。首版要保留跨位置访问、历史入口和重新切入能力，不能用布局简化削掉这些行为。（阶段范围见 P1/P2）
