## 要承载的共同工作

「想创造一个东西，让这个东西协助我和ai，协助我们思考，完成任务，组织调度」。（小林 2026-10-23，经 S01 转引）

项目部分承担其中需要持续投入、分化协作、选择方向与面对结果的工作。它既要让不确定的问题继续展开，也要让已有判断进入行动；研究、建模、写作、代码和现实尝试都能在此留下可继续使用的东西。管理是组织这些活动的能力，不要求活动先成为可打勾的任务。（经过 S01 第二节、S02 主题9及撞过的地方、S04/S07）

一个实际例子：这次“项目部分”已有两个分享分支、结构稿、旧 V1 和多次纠正。需要共同维护的是正在设计的产品及其不同问题，而非把每个聊天各造一个项目。来源仍按原会话存在，工作可以跨会话持续。（依据 S03–S07；例子不是新建项目的操作事实）

## 软件对象的工作含义

以下是为实现操作设定的含义，不给 Cognos 思想中的“空间”“主体”“尝试”下最终定义。（D02）

| 对象 | 承载什么 | 何时独立维护 |
|---|---|---|
| Project 项目 | 稳定名字、当前说明、参与者、工作安排、成果和沿革 | 当一件事值得持续投入；目标可变或暂不清楚。（R05/R06） |
| Location 工作位置 | 项目内部的部分、分支或一个可持续进入的范围 | 需要自己的讨论、组织或采用状态；默认有一个主导航父位置。（Q01） |
| Attempt 尝试记录 | 一次或一段实际开展的思考/行动、意图、简介、阶段经过 | 需要持续跟踪其展开和认识变化时；不要求先有任务或预定步骤。（R04/S08） |
| WorkItem 工作项 | 明确的执行承诺、交付、负责人、依赖和验收 | 当有人承诺完成某件具体事；可以服务一项或多项尝试。 |
| Conversation 会话 | 参与者在特定来源/运行会话中实际交流的历史 | 原会话有独立身份，跨位置引用不复制成多份聊天。（R03） |
| Source 来源 | 实际取得的原文、文件或外部结果及版本 | 需要回查材料或声明的依据时。 |
| Proposal/Claim 方案或判断 | 有作者和版本的解释、设计、挑战 | 某一观点需要比较、复用或修订时；不要求每句话建条目。 |
| Adoption 采用 | 谁在什么范围采用哪个版本、何时重开 | 某观点开始约束共享工作或下一次执行时。（D04） |
| Run/Result 运行与结果 | 真实调用、操作、返回物、验证和交回状态 | AI 或外部工具开展工作时；运行成功与项目目标达成分别判断。 |

这些对象的稳定身份可以互相连接：一个尝试包含多段会话、任务和成果；一个任务可服务多个尝试；一段会话可帮助多个项目。关系说明具体用途，不能只留一个“相关”。（D01/D04）

## 三类不同的分支

项目中的工作分支表示方向或部分，具有自己的位置；会话分叉表示从某节点开展了另一次交流；代码分支是执行产物的版本组织。三者可以互相关联，但创建其中一个不自动创建另外两个。

例如讨论“单层导航还是多层导航”的两条聊天可以关联同一个产品分支；代码试验另有仓库分支；某次聊天里的其他话题还可关联到另一个位置。只有当一条方向需要独立目标、责任或节奏时，才执行[项目重组](开始与重组.md)。

## 项目状态与工作状态

项目候选状态：形成中、活动、暂停、结束、已合并；形成前的自由记录不必先登记“形成中项目”。结束后可重开，记录原因；合并保留原项目身份与去向。工作项候选状态：待开展、进行中、等待、完成、取消。尝试可以进行、停放或结束，允许没有明确结论。

项目活动不表示每项工作都在运行；尝试结束不表示它的判断正确；任务完成不表示某项设计已被采用。界面和模型入口应读到对应对象的状态及依据。

## 这一层怎样算有用

用户可以进入“项目部分”，知道目前有哪些设计、各是谁提出的、哪些已采用、现在可从何处继续；另一位参与者可以选择“数据模型”而非接续最后一次聊天，做出有依据的改进，并让相关位置看到其影响。若只是把旧讨论换成卡片而后续工作没有利用它，产品仍未达到这一目的。（R08、S01 记账收窄纠正；验收见 V02/V03/V10）
