## 一致的版本承诺

首个可用版要让真实工作从开始、形成项目、探索与执行，走到结果、纠正和接续，并能进行基础重组。工程可以逐段实现；只完成存储、消化或上下文，不宣称首版已完成。探索和执行同时进入首版，四端全部能力及复杂多人调度可以逐项扩展。（D06，经过 S04 对旧V1的纠正、S06/S07 的阶段冲突）

## 建设阶段

| 阶段 | 实质交付与先决条件 | 完成凭据 |
|---|---|---|
| P0 设计与来源核对 | 本组文件；选两分支、结构稿、旧 V1 等真实材料；登记缺口及分歧；核当前代码后形成字段映射 | 文档导航和覆盖检查；来源对应；纸面走通 V01–V05。当前仅文档与部分已有纸面记录，不是独立接手续验。 |
| P1 可工作的产品基础 | 原文/版本、名字导航、项目和位置、Initium/直接入口、尝试简介与阶段总结、usage、历史；基础调整/独立/合并 | 实际页面完成 V01/V04/V05，旧来源与链接保持；数据备份恢复演练。 |
| P2 首端共同工作闭环 | 在 P1 上接至少一端：上下文取材、授权读写、方案/采用/纠正、任务、真实执行与可靠回流、暂停恢复 | V02/V03/V06–V10、V12 的真实记录；P1+P2 合起来才可判断首个可用版。 |
| P3 多端与持续协作 | 按能力矩阵接更多端、并发方案、依赖结果、事件与持续委托；深化跨位置影响与恢复 | 每端逐能力回执；并行及失联场景通过；不能以 MCP 工具列表代替。 |
| P4 复杂组织与扩展 | 批量重组、跨项目投入协调、高级管理视图及与其他形态服务复用 | 真实使用暴露的需要和收益；保持前述来源/权限/历史契约。 |

实施先后：首版范围仍是 P1 加 P2，但先让三个真实来回跑通（跨会话接着做、交出去走开回来、几方同时不用传话，见[共同工作怎样发生](../02-协作/共同工作怎样发生.md)七），对象和页面按它们需要的先做，其余再补齐。跑不通的地方回头改设计。

P1 包含基本结构改变，P4 是规模和复杂度扩展；P2 包含首端运行和恢复，P3 是多端长期协作深化。因此不会出现“首版要求重组/执行，实施却全部放首版之后”的冲突。（D06）

### 第 2 段已做的部分（2026-11-03，app 0.22.0，分支 claude/decisions-and-who）

- 在生效的决定：`cognos_decisions` 存原话、原消息或来源说明、原作者（项目主人本人）、登记者（AI 代录时单独记，且必须指向对话里用户那一句、原话能在其中原样找到）、范围（整个项目或列出的位置及其下面）、生效/撤回/被替代和替代关系。撤回和替代只有本人能做，旧记录可查。
- 入口：项目位置的入口最前面是对这一处适用的决定；没有就不写这一段。每次运行在 `cognos_run_decisions` 记下入口里实际给了哪几条。
- 谁在动什么、一条决定走到每个参与者哪一步、交回时「起步时还没有这条决定」：显示在位置页上。结果照收，不自动用到共享内容。
- 按当前候选做的地方：决定和谁在动什么在每个位置页上都显示（决定列表是整个项目的，入口只给适用的）。参与者只列在这个项目里经 Cognos 跑过运行的那几位；叫不醒的网页端固定显示「尚无证据」，并给一段可复制的入口文字。
- 没做到：成果采用/纠正仍未做（委托见下一节）；V12 只覆盖了一端。
- 后补（分支 claude/project-tails，不加迁移）：
  - 依据：agent 做事时可以用 `note_basis` 记下这次依据了哪条决定（照抄原话里的一段，不用记编号）或这一处当前内容的哪一版，记在这次运行上，和交回时的 depends_on 同一处。不记就是「未上报依据」，不推定没有依赖，入口里也不要求它记。
  - 项目总览（`/projects/<项目>`）单独成页：在生效的决定、谁在动什么、各位置现在怎样（当前内容第几版、谁最后改的、正在做的、交出去没回来的、留着待比较的）、最近交回的结果各自上报了什么依据。不再拿根位置页顶替；根位置照常是一个位置。
  - 待比较的两版并排看：委托留下的版本和当前稿、保存冲突时已保存的版本和你的文本，逐行比，只在一边有的行标出来；390px 时上下排。

### 交出去（实施说明第 4 段，2026-11-03，app 0.23.0，分支 claude/delegate-from-project）

- 位置页上「交出去」：一句话，加可选的要做成什么、用什么、不能碰什么、什么时候回来（默认 30 分钟），以及「可以改这一处的当前内容」（默认不勾）。存一条委托（`cognos_delegations`），把填的内容作为一句话留在这个位置的讨论里，经桥交给本机 Claude Code；运行挂在委托上（target_type = delegation），出现在「谁在动什么」，结果回到这个位置的讨论。
- 允许改内容时，Claude Code 用 `write_content` 交回全文：这一处从交出去时的版本起没被改过、也没有它输入里没有的新决定，就提交成它署名的新版本（`cognos_location_revisions.delegation_id` 指回委托）；否则不覆盖，留在委托上作为待比较的版本，页面上能看、能放进编辑区比较。没给权限时 `write_content` 被拒，结果只是回答。
- 按当前候选做的地方：「什么时候回来」只是约定，过了时间页面写「还没回来」，不替它停下（桥自己的总时限仍是 30 分钟）；改内容只接受全文，不做合并；交出去只接本机 Claude Code（creation_agent = claude-code）；同一处同时只做一件，桥正忙就记成「没交出去」并写明原因，不排队。

### Initium 和确立（实施说明第 5 段之一，2026-11-03，app 0.24.0，分支 claude/initium）

- Initium（`/initium`）按当前候选做成聚合视图，不是新的一种东西：列出还没成为项目位置讨论的会话，带第一句、已促成哪些项目、AI 是否正在做。一句话或一个链接就能留下（建一段会话，第一句就是它）；可以勾「留下后让 AI 先试一下」，或之后点「让 AI 试一下」（拿第一句叫，不另存一句）。首页和项目列表都有入口。
- 确立：在一段会话里勾出促成它的那几句（默认勾第一句），起名字，可选写初步说明和理由，成为新项目；也可以成为已有项目的又一段来路。`cognos_project_formations` 记下 formed_from（会话、那几句、谁、什么时候、为什么）。原会话不搬动、不改写，作为材料关联到根位置（用途写「来路：……」），还能接着聊；项目另有自己的讨论。初步说明是根位置的第 2 版，指回那几句，不顶替原话。一段会话可以促成几个项目，一个项目可以有几段来路。项目总览上有「来路」一块，原话原样引用。
- 顺带改的：入口里，项目位置没有适用的决定时写一句「这一处现在没有在生效的决定。」；不在项目里的空间不写这句，也不给 note_basis。起因是 Claude Code 在 Initium 里试的时候说分不清「没有」和「没给」，而且没有决定却被要求照抄决定原话。
- 没做到：从笔记或外部链接直接确立（现在要先在 Initium 留成一段会话）；确立时同时开启 AI 持续工作（设计要求先有委托边界，这里不做）；附件、尚未取得的材料提示。

### 采用和纠正（实施说明第 5 段之二，2026-11-03，app 0.25.0，分支 claude/adoption-correction）

- 按数据模型的首版：想法、反对、回应仍在只增不改的发生表里，只把采用另开一张表（`cognos_adoptions`）；纠正（`cognos_corrections`）和它造成的影响（`cognos_impacts`）各一张。
- 采用：某个位置采用一样东西的具体一版。现在能采用的是一段回答（这里的讨论或这里用作材料的会话里的一句）和同一项目里某处当前内容的某一版。一处一条：在甲处撤回只改甲处，采用了同一样东西的别处只得到提示。改采用别的一版时，旧的标为被替代，留着。
- 纠正：指向具体一样东西的具体一版，留下纠正的原话、谁、依据。明确依赖这一版的进待复核：采用了这一版的位置，以及交回时报了它作依据的运行。只是相关的只提示：采用了别的版本的、把它所在的会话用作材料的、它所在的讨论或当前内容。同一原因对同一目标只记一条。
- 面对：待复核的采用可以「仍然采用」（必须写回应）、撤回，或改采用别的一版；提示可以标「知道了」，运行结果的待复核写一句怎么处理的。纠正、回应、撤回、被替代都留着可读。项目总览上各位置显示几件待复核。
- 按当前候选做的地方：只有项目主人自己能采用、纠正、处理，AI 在委托里采用还没做；纠正只看一层（直接采用和直接报依据的运行），不往下传；被纠正的东西本身不改，也不自动撤回任何采用；发生表里的想法还不能在项目位置上被采用。

### 重组（实施说明第 5 段之三，2026-11-03，app 0.26.0，分支 claude/restructure）

- 首版做三种：调整位置（同一项目里换上级）、独立成项目（一处连同下面的成为新项目，它成为根位置）、合并项目（整个项目并到另一个项目的某处下面）。工作拆分、退回自由探索、暂停或结束、撤回一次重组还没做。
- 先预览后确认：预览写出后果（路径怎么变、哪些按范围登记的决定开始或不再管到它、哪些决定跟着走或留下、正在做的工作、跨项目的采用），带一个受影响状态的摘要（basis）；确认时状态变了就整批不做（409），请人重看预览。
- 位置和项目的 id 都不变，旧链接照样打开，位置页显示当前所在项目；每个受影响的位置记下当时在哪、去了哪（`cognos_location_history`），位置页和项目总览上都能看到。被合并的项目身份留着，总览上写明合并到了哪、链过去，项目列表里标「已合并到」。
- 按当前候选处理决定：独立时，只管移出去那部分的决定跟着走，整个项目的决定留在原项目（预览里列出，需要就在新项目里重新登记）；合并时，源项目整个项目的决定改成只管原来那部分，目标项目整个项目的决定从此也管到这部分（预览里都列出）。委托和采用跟着位置走，改记到新项目。
- 没做到：权限、访问范围的变化（试用里只有项目主人一个人）；Initium 来路随合并移动（留在被合并项目上，照样可读）；重组撤回。

### 第二个参与者和 V12（实施说明第 5 段之四，2026-11-03，app 0.27.0，分支 claude/second-participant）

### 委托内采用和纠正多传一层（2026-11-04，app 0.28.0，分支 claude/delegated-adoption）

- 交出去时可以勾「可以在这一处采用」。正在做这件事的 AI 用 `adopt` 在那一处采用时直接生效：采用者记它，`authority` 记那次委托，`source_message_id` 记用户交出去时那句话。不在范围内（没给采用的权限、不是交出去的事、自己登记进来的参与者）就只记成它的提议（state = proposed），用户在页面上「采用」（采用者变成用户，提议者留着）或「不采用」（留着，标为没有采用）。
- 纠正多传一层：第 1 层是直接依赖那一版的（采用它的位置、报了它作依据的运行），进待复核；第 2 层是采用了它的位置上、在采用期间交回的结果和之后写的当前稿，也进待复核；第 3 层（别处采用了那些当前稿版本的、报了它们作依据的运行）只提示，页面写「纠正传到这里为止，再往下不追」。第 2 层按时间判断「在采用期间」，不推定那次结果真的依据了它。
- 顺带改的：交出去时写进讨论的「什么时候前回来」原来用容器里的 UTC，Claude Code 看到的期限和它自己的时间差了 8 小时，在回答里指了出来；现在按用户的时区（没设就按入口用的 Asia/Shanghai）。可复制的入口文字里的时间同样改了。
- 没做到：AI 在委托里撤回、改采用别的版本；采用权限只到「这一处」，不能写成几处或整个项目。
## 内容验证与工程验证分开

工程检查覆盖身份、版本、事务、权限、幂等、恢复和旧链接；真实内容检查覆盖是否找对对象、经过旧纠正、保留互斥判断及做出有用改变。测试全部通过，只能支持工程契约，不能证明 AI 已学会真正思考或 Cognos 已形成主体。（S01/S02；S01 的被接住押注与实现失败）

内容验证可让接手者独立指出：一条用户选择、一条 AI 候选、一处来源缺口、一条旧纠正、当前可推进的一项工作。核它实际引用和新增成果，不要求固定回答格式，也不把背诵本文当成功。

## 衡量是否值得继续

观察用户补搬上下文的负担、错误确认率、关键纠正的实际影响、旧成果的使用、从其他位置进入的顺畅度和完成工作的质量；记录具体误解和被接住的新尝试。没有可靠对照前不用精确分数宣称改善。（S07 §22、S01 第二节）

范围变化要同时修改此阶段表、总纲和对应验收项；不以“之后再做”掩盖已承诺首版缺项。新的使用暴露核心关系错了，可以重构；保留被改变的依据和旧产物，具体差异进入分歧台账。
