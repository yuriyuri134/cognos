## 一致的版本承诺

首个可用版要让真实工作从开始、形成项目、探索与执行，走到结果、纠正和接续，并能进行基础重组。工程可以逐段实现；只完成存储、消化或上下文，不宣称首版已完成。探索和执行同时进入首版，四端全部能力及复杂多人调度可以逐项扩展。（D06，经过 S04 对旧V1的纠正、S06/S07 的阶段冲突）

## 建设阶段

| 阶段 | 实质交付与先决条件 | 完成凭据 |
|---|---|---|
| P0 设计与来源核对 | 本组文件；选两分支、结构稿、旧 V1 等真实材料；登记缺口及分歧；核当前代码后形成字段映射 | 文档导航和覆盖检查；来源对应；纸面走通 V01–V05。当前仅文档与部分已有纸面记录，不是独立接手续验。 |
| P1 可工作的产品基础 | 原文/版本、名字导航、项目和位置、Initium/直接入口、尝试简介与阶段总结、usage、历史；基础调整/独立/合并 | 实际页面完成 V01/V04/V05，旧来源与链接保持；数据备份恢复演练。 |
| P2 首端共同工作闭环 | 在 P1 上接至少一端：上下文取材、授权读写、方案/采用/纠正、任务、真实执行与可靠回流、暂停恢复 | V02/V03/V06–V10、V12 的真实记录；P1+P2 合起来才可判断首个可用版。 |
| P3 多端与持续协作 | 按能力矩阵接更多端、并发方案、依赖结果、事件与持续委托；深化跨位置影响与恢复 | 每端逐能力回执；并行及失联场景通过；不能以 MCP 工具列表代替。 |
| P4 复杂组织与扩展 | 批量重组、跨项目投入协调、高级管理视图及与其他形态服务复用 | 真实使用暴露的需要和收益；保持前述来源/权限/历史契约。 |

实施先后：首版范围仍是 P1 加 P2，但先让三个真实来回跑通（跨会话接着做、交出去走开回来、几方同时不用传话，见[共同工作怎样发生](../02-协作/共同工作怎样发生.md)七），对象和页面按它们需要的先做，其余再补齐。跑不通的地方回头改设计。

P1 包含基本结构改变，P4 是规模和复杂度扩展；P2 包含首端运行和恢复，P3 是多端长期协作深化。因此不会出现“首版要求重组/执行，实施却全部放首版之后”的冲突。（D06）

## 贯通场景与通过标准

以下是待执行验收，不是本次完成事实。实际执行时为每项附日期、环境/代码版本、参与者、输入、操作、结果、反例和证据路径；失败保留。

| 编号 | 场景及做法 | 必须看见的结果 | 阶段 |
|---|---|---|---|
| V01 | 无项目的会话谈两件事，选其中一段确立，再补一段来源 | 原会话与另一话题仍在；项目增加稳定入口；取得范围真实 | P0纸面/P1实际。 |
| V02 | 参与者B在新会话打开“项目部分”，不由用户重讲背景；从数据模型进入而非续写末条 | B找到旧V1和D06，区分用户与AI，能提出并保存有依据的新工作 | P2。 |
| V03 | 对一项已采用判断提出反例；甲处依赖，乙处仅参考 | 甲进入复核并按权限变更，乙只获相关提示；旧观点与反驳可读 | P2。 |
| V04 | 同一会话关联两个位置，分别选段、用途、版本策略，后来补消息 | 来源身份一致，用途和采用独立，新增范围可查，不重复复制原文 | P1/P2。 |
| V05 | 调整分支、让其独立、再合并一项工作；打开旧链接 | 当时位置与当前去向都可找，运行回指正确，多处采用与权限不被扩大 | P1基础/P3并发。 |
| V06 | 一端执行真实任务，AI先说完成，工具随后失败，修复后再验证 | 执行声明、失败回执、成功产物、验证及采用分别呈现 | P2。 |
| V07 | 两位在同版本修改共享安排；同一请求重试；同ID改请求内容 | 首次生效一次；并发不覆盖；同ID异内容冲突；独立提案均保存 | P2/P3。 |
| V08 | 运行领取后退出、外部动作后未回执、结果已存但投递失败；再暂停项目 | 能区分未知与已完成；不盲目重放；结果重投只生效一次；暂停后不新领工作 | P2基础/P3多端。 |
| V09 | 提供仅预览、缺附件、无权来源和过期索引；导入重复与编辑消息 | 缺口真实、权限有效、旧版本可回读；不把摘要冒充原文，不因索引漏项判不存在 | P1/P2。 |
| V10 | 纯理论工作没有代码产物；比较旧设计、反例与新结构；回来从另一处进入 | 有可继续使用的新判断或问题结构，能指出改变与未决，调用次数不冒充成果 | P0内容/P2实际。 |
| V11 | 备份后恢复来源、修订、运行和待发送结果；重建投影 | hash/版本/采用/权限一致，未交回结果仍在，恢复不重做外部动作 | P1存储/P2运行。 |
| V12 | 两个以上参与者（例如本机 Claude Code 和一个聊天端会话）同时在同一项目工作；中途小林做出一条新决定；其中一位改了另一位正在依据的文档 | 项目页上看得见谁正在动什么，以及新决定对每一位走到了哪一步（存下、送到、读到、照着做）；接得上的参与者，新决定在它下一次动手前出现；接不上的（叫不醒的网页端），页面如实显示它还不知道，它交回东西时差异被拦下；依据被改的那一位在交回前看到差异；小林不用自己记谁知道了什么 | P2基础/P3多端。 |

## 内容验证与工程验证分开

工程检查覆盖身份、版本、事务、权限、幂等、恢复和旧链接；真实内容检查覆盖是否找对对象、经过旧纠正、保留互斥判断及做出有用改变。测试全部通过，只能支持工程契约，不能证明 AI 已学会真正思考或 Cognos 已形成主体。（S01/S02；S01 的被接住押注与实现失败）

内容验证可让接手者独立指出：一条用户选择、一条 AI 候选、一处来源缺口、一条旧纠正、当前可推进的一项工作。核它实际引用和新增成果，不要求固定回答格式，也不把背诵本文当成功。

## 衡量是否值得继续

观察用户补搬上下文的负担、错误确认率、关键纠正的实际影响、旧成果的使用、从其他位置进入的顺畅度和完成工作的质量；记录具体误解和被接住的新尝试。没有可靠对照前不用精确分数宣称改善。（S07 §22、S01 第二节）

范围变化要同时修改此阶段表、总纲和对应验收项；不以“之后再做”掩盖已承诺首版缺项。新的使用暴露核心关系错了，可以重构；保留被改变的依据和旧产物，具体差异进入分歧台账。
