# 项目：结构与核心点（11/03）

〔AI 11/03〕在定下来的「第 4 版 + 苗圃 + 确立」上往前推结构，不换方案，不写细节。

## 一、结构：四层，一条写入路

1. **进来**：会话、想法、笔记、跑出来的结果，先落进苗圃，原样留着。还要能看见哪些没进来。
2. **苗圃 → 确立**：一个东西被起名、选成「项目」，才进项目空间。没确立的留在苗圃，带着起点、停在哪、什么时候值得回来。
3. **项目里有三样东西**：
   - **发生**：原样记下的一切，只增不改。
   - **现在的样子**：这个项目此刻是什么、停在哪、往哪走。它是一种读法，可以被纠正、被重切，旧样子留着。
   - **没完的**：每件写着下一步欠在谁那、什么时候值得回来。
4. **两个出口**：
   - **项目页**给人看，从「现在的样子」和「没完的」生成。
   - **入口**给 AI 读，同样从这两样来，但按 AI 干活要的取，不是同一段文字。

一条写入路：**消化**。每次在项目里聊天或干活，结束时都消化成几条候选的**移动**，比如改了现在的样子、开了一件没完的、关了一件、停在了哪。人扫一眼确认，移动才写进去。**纠正**也走这条路，纠正一条移动或一处现在的样子，原来的留着。

**守望**不按时钟醒，盯的是每件没完的「什么时候值得回来」：PR 有动静、一次运行跑完、另一个项目碰到它。条件到了，就把它放回项目页最上面，或者把该接的那位叫回来。

## 二、核心点

1. **消化是唯一的写入路，也是最难的一步。** 消化不发生，项目页就会过期，又退回记账。这次手试就证明了：排一页要读完三次上传、八份会话，难在消化，不在排版。〔AI 65%，最可能碎在：你觉得核心是守望，也就是 AI 自己往下推，不是消化〕
2. **人看的和 AI 读的分开。** 现在侧栏和 AI 入口是同一段文字，所以两头都别扭。
3. **「现在的样子」是读法，不是记录。** 它能被你推翻、整个重切；发生不动。这样「全部错了重新想」有地方落，不用清空历史。
4. **移动先是候选。** 第一版全由你确认；以后哪些移动 AI 可以自己定，从你确认的记录里看出来，不预先规定。
5. **苗圃要能把没吃进来的显出来。** 111 档案那条线就是这个需要；吃不进来的，至少标明缺着。

## 三、旧机制的去留（结构上的判断）

〔AI 60%〕项目是一种空间，底子沿用现在的三样：发生（traces）、读法（readings）、没完的（open / stop）。新加的只有三处：「现在的样子」、消化出移动、给人看的项目页。押着前提、被顶叫回来那一套，先不进项目，留在创立空间里。

会碎在：「现在的样子」用一条读法装不下，需要自己的结构；或者没完的（open）现在的停法（接着、卡住、完了）不够写「欠在谁那」。

## 四、第一刀的顺序

项目页（先用手排的那份）→ 消化 → 纠正 → 守望。苗圃和确立先做到最薄：能记、能起名、能选「项目」。
