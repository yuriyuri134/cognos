## 两套设计是什么关系

两套是分别写的。GPT 那套读过 Claude 的第二版结构稿（它的 S05）和 GPT 自己更早的两份方案；没有读到后来的「往深处想」和「项目部分设计」。Claude 那份读过 GPT 的整合方案，没有读到这套分层设计。

### 一致的地方

- **开端**：不用先建项目就能记、能聊、能试，名字叫 Initium；值得持续做时再确立，确立带来稳定入口，原来的会话成为来路。
- **原文和解释分开**：原文只增不改；当前理解、采用的方案、纠正都另外记，旧的留着。
- **纠正**：指向具体的一个判断，不抹掉旧的，受影响的工作要重新看。
- **不逐条等确认**：按范围委托，范围内直接做，越界才问。
- **结果一定回得来**：两边都指出桥把结果发回失败就丢了。GPT 那套把这件事设计到了底：领取、租约、待发送队列、同一结果只生效一次、外部动作状态不明时怎么办。
- **选下一件不按编号**：每次要说清为什么现在做这件。
- **思考类工作算什么进展**：提出新结构、排除一种解释、打开以前看不见的问题，都算；调用次数和文字长度不算。

### Claude 这份改从 GPT 那套的地方

- **回来时不一定是接着做。** 小林 6/28 说过「我回来往往也不是继续，而是沿着这个大方向，但不是最后的位置，是另个位置」。GPT 那套据此让项目页同时支持接着做、从另一个问题展开、整体重新看；Claude 这份把「前沿」放在最上面，偏向了接着做。这一点 GPT 那套更贴近小林的原话。
- **会话消化**：不止当场留，也要能事后把聊天端的会话读进来，这点在 GPT 那套里写清了，Claude 这份只想到了经过桥的运行。
- **同一份材料在不同地方怎么用**：GPT 那套给每一处单独记用途和采用，一处推翻不会连带别处。Claude 这份只说了「谁读过它」。两者可以合起来：读过的记录找出可能受影响的地方，各处的用途记录决定受多大影响。

### GPT 那套可以补上的地方

- **在生效的决定。** 小林本人说过、对所有参与者都有效的决定（比如不再出新方案、苗圃改叫 Initium、不用押顶碎和百分比），单独放一块，每个参与者进来先看到。GPT 那套把决定当成按位置记的采用记录，没有这样一块。11/03 上午几个 AI 同时改文档、其中一个回复里还在用已经被小林取消的说法，缺的正是这个。
- **选下一件看什么。** GPT 那套要求说明「为什么现在做它」，没说看什么。Claude 这份列了几样：挡着别的事吗、放着会越来越难做吗、是小林正在疼的地方吗、会碰到现实吗、我能动它吗。
- **项目是往前推的那一方。** GPT 那套把它留作解释上的假设，不进结构（它的 D02）。这是两边最大的不同，还没有定。

### 第一版的大小不同

GPT 那套的首个可用版是 P1 加 P2：名字导航、Initium、项目和位置、尝试、各处用途、历史、基础的拆分合并，再接通一个真实运行端，走完委托、执行、可靠回流、纠正、暂停恢复。Claude 这份的第一版只要跑通两件事：小林交出去一件事、走开、回来看到结果；几个 AI 同时在做时不用小林传话。前者完整，后者更快能用上。
