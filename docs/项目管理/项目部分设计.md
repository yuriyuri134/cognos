2026-11-03。这是项目这一块的完整设计，把之前几份稿子合成一份：

- 11/02 定下来的第 4 版、苗圃（现在叫 Initium）、确立；
- 第二版结构稿；
- GPT 的整合方案；
- 「往深处想」。

那几份留作来路，以这一份为准。这里只讲设计，不写代码怎么实现。

## 一、为了什么

小林在会话 4 里说，要的是「一边做出一个能够带来真正思考，或者能够以一个我比较满意的思考不断回复我的一个整体」。10/27 认下的方向是：会思考的是 Cognos 这个整体，模型是它的器官，小林也是它的一部分。

项目这一块，管的是这个整体怎么持续地做事：

- 一件事从冒出来到被做成，中间不会因为一次会话结束就断掉；
- 小林不在的时候，它也能接着往前走；
- 几个 AI 同时在做时，彼此知道对方在干什么；
- 小林回来的时候，不用当传话的人，也不用从头讲一遍。

第一版只有「项目」这一种形态。底子按共用的做，以后笔记、学习、组织、创作都长在同一个底子上。

## 二、里面有什么

### 1. Initium

所有还没成为项目的开端，都放在这里：一个想法、一段会话、一个问题、一股不满。

每一条至少留住五样东西：

1. 原来的问题，用小林的原话；
2. 当时怎么推的；
3. 碰到了哪些限制；
4. 还有哪些路没验证过；
5. 当时那股劲，也就是它为什么会冒出来。

前四样来自会话 1 自己留下的检验：「半年后重新打开 ABC，能不能找回原来的问题、当时怎么推的、碰到的限制、没验证的路。」第五样是因为，只留内容不留劲，半年后打开的只是一份资料，接不着走。

Initium 里的东西也可以被推。AI 可以对它做一次小的试探，看它有没有劲、会长成什么，试探的结果也留下来。

现在 Initium 里应该有的几条：111 档案、转机那条线、ABC、「一个存在能怎么存在」、「尝试有哪些方式」。后三条是一根藤上的。

### 2. 项目

一件被确立下来、要持续做下去的事。每个项目有这些部分：

| 部分 | 是什么 |
|---|---|
| 为了什么 | 这个项目往哪走。由小林给，可以改。 |
| 前沿 | 现在正在推的、下一步是什么、卡在哪。一个项目可以同时有几个前沿。 |
| 没完的事 | 每件写着：要做成什么、谁能动它、什么时候值得回来。 |
| 现在的理解 | 这个项目此刻是什么样子。可以被纠正，也可以被整个重新理解，旧的留着。 |
| 经过 | 发生过的一切，只增不改。它的用处是让下一步一出手，就知道这条路以前有没有走过、在哪撞过。 |
| 部分 | 项目可以分出下属部分，部分也可以独立成项目。 |
| 来源 | 会话、文件、代码、外面查到的东西。每份有自己的身份和版本，同一份可以被几个项目用。 |

### 3. 参与者

在项目里做事的每一方都是参与者，各有各的手：

| 参与者 | 能做什么 |
|---|---|
| 小林 | 定方向、做决定、在本机动手、说出只有他知道的事 |
| 本机 Claude Code（经过桥） | 在小林电脑上读写代码、跑命令、跑 8780 |
| Hermes | 在 Cognos 里对话、搜笔记、建笔记 |
| 云端 Claude（这里的线程） | 读仓库、想设计、开 PR；开了 Remote Control 才能碰本机 |
| 聊天端 Claude、GPT 网页版 | 只能读到小林贴过去的东西，结果由小林带回来 |

每个参与者正在动什么，项目里都看得见，比如「GPT 正在改项目管理的文档」「本机 Claude Code 正在跑 111 的真实数据」。这就是最小的组织：项目一有两个以上的参与者，就需要它。所以组织不是以后的事，从第一天就在项目里。

### 4. 在生效的决定

小林本人明确做过、对所有参与者都有效的决定，单独放一块。每条写着日期、原话、管到哪里，可以撤销。现在就有的几条：

- 11/02：方案就是第 4 版加 Initium 和确立，不要再出新方案。
- 11/03：苗圃改叫 Initium。
- 11/03：不用押、顶、碎、百分比、来源标签、六问七问、固定的开头结尾。

每个参与者进入项目，第一眼看到的就是这一块。

这里只放小林自己说的话，不放 AI 总结出来的原则。这样它不会长成新的一套「每次先读一遍的规矩」，那正是 11/03 刚删掉的东西。

### 5. 委托

小林把一件事交出去，用一句话。比如：

> 「111 这件，你在我电脑上用 Claude Code 拿一个真实的子会话走一遍：取得、完整保存、另一个会话读到、核对有没有漏。用 Pro 的额度，别动我 ChatGPT 账户的设置。走通了或者卡住了告诉我。」

一次委托里有五样：

1. 要做成什么；
2. 用谁的手；
3. 花什么；
4. 哪里不能碰；
5. 什么时候回来。

小林没说的部分，项目自己补默认：

- 手和额度，沿用这个项目已有的委托；
- 不能碰的，默认是改生产、对外发出、删除、动账户；
- 什么时候回来，默认是做成、卡住，或者额度花完。

在委托之内，接手的参与者自己选怎么走，碰到路不通就换路，换了什么记下来。只有目标本身得改，或者要碰不能碰的地方，才回来问。

### 6. 叫醒条件

每件没完的事都写着什么时候值得回来，比如：

- PR 有了动静；
- 一次运行跑完了；
- 小林说了一句碰到它的话；
- 它依赖的另一件事做完了；
- 它读过的东西变了。

条件到了，这件事就醒过来，交给能动它的参与者。不按时钟醒。

## 三、它怎么动

### 1. 从 Initium 到项目：确立

一个开端需要成为项目，是在一次会话装不下它的时候：它要第二次回来，要换一个参与者接手，或者要换一个地方动手。

所以一条 initium **第二次被碰到**时（又一个会话提到它，或者别的项目引用了它），Cognos 把它提到小林面前：这个又被碰到了，要不要给它一个会留下来的位置。小林起个名字、说一句为了什么，它就成了项目。几条 initium 也可以一起确立成一个项目。

确立以后，内容不变，多出来的是三样：

- 一个会留在会话之外、首页看得见、别处能引用的位置；
- 可以被委托出去；
- 有了叫醒条件。

项目也可以退回 Initium。比如转机那条线，现在其实就是只剩一个想要、还没有方向的状态。这不算失败。

### 2. 一次推进

任何参与者在项目里做一段事，都是一次推进，走法都一样：

1. **进来先看三样**：在生效的决定；自己上次以后，自己读过的东西有什么变了；自己被委托的是什么。
2. **选这一次做什么**：见下一条。
3. **做**。
4. **走的时候当场留下挪动了什么**：前沿挪到了哪、开了或关了哪件没完的事、现在的理解哪里变了、停在哪、为什么停。

第 4 步就是第 4 版里的「消化」，只是不再由别人事后去读一大堆会话来整理，而是谁推的谁当场留。挪动按委托范围直接生效，小林事后可以纠正。

### 3. 选下一件

不排一条统一的队。每个参与者进来时问的是：**以我手上的能力，现在能让这个项目挪得最多的是哪一件？**

看这几样：

- **它挡着别的事吗？** 比如本机身体分支没推，后面好几件都卡着。
- **它放着会越来越难做吗？** 比如分支越放越歪，会话越积越多。
- **它是小林现在正在疼的地方吗？**
- **它会碰到现实吗？** 回看会话 1 到 8，让人意外的发现，全来自和外面的东西接触。
- **我能动它吗？** 云端的我动不了本机分支，本机 Claude Code 能。

小林看到的「下一件」，总是只有他能做的那一件。

项目还记得过去哪种工作真的让它挪动了，哪种只是多了一页字，下一次选的时候会参考。10/27 晚上 Cognos 自己连跑 8 次，全在修自己的管道，思考那一侧没动。有了这份记录，它就能知道光修管道不算推进。

### 4. 变化传到受影响的地方

不用谁去登记「谁用了什么」。

- **经过桥的运行**：桥已经存下了每次运行读过的完整输入。一次运行读过什么，就是它站在什么上面。某一块变了，最近读过这一块、又还开着的工作，就是受影响的。
- **聊天端和 GPT 网页版**：它们读的就是小林贴过去的东西，所以贴出去的时候记一笔。

受影响的一方不是收到一条通知就算了，而是下一次动手前，先看到这个变化（见「一次推进」第 1 步）。小林的新决定也是这样传：一落下，所有参与者下一次进来都先看到它。

已经结束的工作不叫回来，只有有人再打开它时才提示，免得一个文件一改，几十次运行全被叫醒。

### 5. 纠正

小林或别的参与者发现一个挪动不对，就纠正它。纠正指向具体的那一个挪动或那一处理解，原来的留着。

被纠正的挪动是谁做的，就叫谁回来面对这一下。那位已经不在了，就叫回接手的参与者。站在被纠正的东西上面的工作，按第 4 条一样受影响。

### 6. 结果一定回得来

自主做事的前提是：做完的结果不会丢。现在桥把结果发回 Cognos 失败时，只写一行错误日志，结果就没了。

项目这一块要求：

- 每次运行有自己的身份，记着起步时基于什么、读了什么、做了什么；
- 结果没交回之前一直留着待交，可以重试，同一个结果只生效一次；
- 已经对外做了的动作（比如推了代码），重试前先核对，不重复做。

### 7. 项目的生命

项目会分出部分、部分独立、几个项目合流、睡着、醒来、停掉、复活。旧链接和经过一直找得到。

一个项目的成果，可以是另一个项目碰到的现实。比如 Cognos 做出一个能用的东西，就是转机那条线碰到的现实。

## 四、思考类项目怎么算往前走

代码有测试、有运行，会回答；纯思考的项目没有。这是之前 AI 总往代码漂的原因。

思考类项目算往前走，是这三种情况：

1. **问题变了形状。** 能问出以前问不出的问题，而且新问题打开了更多可能。收窄成一个能答的小问题，不算。
2. **碰到了外面的东西，结果可能让人意外。** 比如：
   - ABC 可以拿模型做实验：一段很短的输入，能不能稳定触发多步处理，两段这样的输入能不能组合。
   - 「尝试有哪些方式」可以拿小林自己一年来的尝试记录当材料，看实际用过哪些方式。
3. **被别的项目用上了。** 「项目本身是一个存在」这个想法，来自会话 2、7 那条线，今天被用进了项目设计。这就是那条线的一次推进。

不算往前走的：多一组区分；换一套说法把同一个位置再走一遍；从抽象落到几个例子就停。

小林要的是更多的可能，不是更精确，所以这里不用「更清楚了」来衡量。

## 五、小林看到什么，AI 读到什么

两者从同一批东西来，但不是同一段文字。

### 首页

按名字列出项目和 Initium，小林自己决定怎么排。首页上的「项目」不再跳到 Deck。

### 项目页（给小林看）

从上往下：

1. **谁正在动什么。**
2. **只有你能做的那一件。**
3. **在生效的决定。**
4. **你不在的时候推到了哪、什么变了。**
5. 前沿、没完的事、部分、经过，往下翻才看到。

### 入口（给 AI 读）

1. 在生效的决定；
2. 自己上次以后，自己读过的东西有什么变了；
3. 自己被委托的是什么；
4. 项目的其余部分，用到哪取到哪，不一次全塞进去。

## 六、和现在的代码是什么关系

**能直接接着用的：**

- Nextcloud 的登录和文件；
- 空间里的发生、读法、没完的事（它们就是项目的「经过」「现在的理解」「没完的事」的底子）；
- `ContinuationService` 的挂起、接着走、额度；
- `PushBackService` 的叫回来；
- 桥：本机 Claude Code 怎么被叫起来，以及它存下的每次运行输入；
- Activity 的来源快照和对话；
- Deck 的卡片，作为具体执行的一种承载；
- Hermes 的对话。

**要新做或者改的：**

- 项目本身：名字、为了什么、前沿、部分、来源关联；
- Initium 和确立；
- 参与者，以及谁正在动什么；
- 在生效的决定；
- 委托；
- 选下一件：从按编号，改成每个参与者按价值和自己的能力来选；
- 变化传播：用桥存下的输入找受影响的工作；
- 结果可靠回流：运行身份、待交、重试只生效一次；
- 人看的项目页和 AI 读的入口分开。现在 `SpaceEntryService::renderText()` 是同一段文字。

## 七、第一版

第一个项目是 Cognos 自己，因为小林每天都在用它，问题当天就会暴露。

第一版做到能跑通下面两件事就够：

1. **小林交出去一件事，走开，回来看到结果。** 一句话的委托，本机 Claude Code 在范围内接着做，结果一定回得来，小林回来时项目页告诉他推到了哪、哪一件只有他能做。
2. **几个参与者同时在做时，不再需要小林传话。** 项目页上看得见谁在动什么；小林一做决定，所有参与者下一次进来都先看到它；一份文档被改了，读过它的、还开着的工作下一次动手前先看到。

为了这两件事，第一版要有的是：

- Initium 和确立，最薄的样子：能记、能起名、能确立；
- 项目页；
- 参与者和谁在动什么；
- 在生效的决定；
- 委托；
- 结果可靠回流；
- 每次推进当场留下挪动；
- 读过的东西变了能被看到。

部分的拆分合并、跨项目成果、几种形态，放到后面。

## 八、拿今天上午走一遍

11/03 05:05 到 05:50，真实发生的是：

- 我在 PR #23 的分支上写结构稿；
- GPT 在同一个分支上提交了整合方案，改了我的 README；
- 另一个线程按小林的决定，把押碎和百分比从记忆和仓库里删掉；
- 我往一个刚被删掉的记忆文件里追加了一段，回复里还在用「押」；
- 小林在中间来回转述，说「我已经要疯了」。

如果这套设计在：

- 小林说「全部去掉押碎这些」时，这句话进了「在生效的决定」。我下一条回复之前就会先看到它，那条带「押 65%」的回复不会出现。
- GPT 开始改 PR #23 时，项目页上写着「GPT 正在改项目管理的文档」。我会先看它改了什么，再接着写。
- 另一个线程删记忆文件时，它在动什么是看得见的。我追加之前会看到那个文件已经没了。
- 小林回来时，项目页第一块就是三个参与者各自在做什么、做到了哪，他不用转述任何一句话。

## 九、还没定、要小林来定的

1. **委托能放多宽。** 比如本机 Claude Code 能不能自己合并到本机分支、能不能自己重启服务。10/27 小林选过「放开，本机自动合并重启」，那一条要不要放进在生效的决定里。
2. **「第二次被碰到就提出来确立」会不会太吵。** 小林的想法很多，可能要换成一段时间汇总提一次。
3. **聊天端的规划定稿原文。** 如果它和这份有冲突，以小林说的为准。
