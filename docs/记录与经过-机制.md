这张表本身就是这件事要防的那个错的一个例子：协调者 22:24 写进项目记忆时，把「知道自己在哪是最底下那一层」记成了小林的原则〔查〕。小林引用了它、没有否定，补了一句「取决于视角」，可这句的作者和把握还是 AI 的 30%。已在记忆里改正。

〔AI 70%〕小林贴 AI 的话回来，是在拿它们当材料往下想，不是在署名。所以：**小林消息里出现的句子，先去对一下是不是 AI 之前说过的，再标来源。**

所以这件事有三部分：
1. **记**：有价值的东西出现时就记下来，标好来源。
2. **放**：放在下一个 agent 最容易看到的地方。
3. **经过**：思考的时候，真的经过它们。

还有一部分是**历史**：把以前所有会话里的这些东西翻出来（见第五节）。

## 二、先自己回答的几个问题

### 问 1：什么算「有价值的东西」？

〔AI 70%〕不只是小林的原话。按小林这两天被丢掉、又得重新说一遍的东西来看，有这几类：

1. **小林的想法**：关于认识、存在、主体、尝试、空间、组织的原话。（思想总索引已有。）
2. **小林的纠正**：他说「不对」「我只是类比」「没抓住重点」的地方，以及他为什么这么说。这一类最容易丢，因为它散在线程里，而且下一个 agent 会再犯。
3. **结构**：从一次纠正里浓缩出来、能带到别的项目的东西。例如「先问三件事」。〔AI 21:42，小林回「对的」〕「答案会过期，结构能带到任何项目」。
4. **过程**：一次推进是怎么走的、在哪里偏了。〔原 10/24 21:21〕「你怎么没有给我完整的过程？」
5. **每个东西是什么**：一句话当时在做什么（下定义、举例、类比、提问、随口一提），作者是谁，把握多少。〔原 10/24 22:24〕「理解和认识每个信息甚至是存在」。〔AI 60%〕这一条我理解为：不只记内容，还要记它是一个什么样的存在。
6. **没解决的问题和张力**。

判断标准〔AI 65%〕：下一个进来的 agent，如果不知道这件事，会不会再去问小林一遍、再犯一次同样的错、或者把它当成新想法再提一遍？会，就值得记。

### 问 2：什么叫「最容易被看到的地方」？

〔AI 75%〕不是「最显眼的文件」，是**不用 agent 自己决定去读，就已经在它眼前的地方**。

证据：PROJECT-OVERVIEW 开头写着「任何 agent 进入本项目先读这一份」，三轮推演里九个 agent 和主持都没读〔查，多 Agent 推演 21:34〕。「先读我」要靠 agent 自己决定去读；而它不知道自己该读，正是问题所在。

每种 agent 都有几个会被自动塞进上下文的地方：

| agent | 自动看到的 | 说明 |
|---|---|---|
| claude.ai 这个项目的协调者和线程 | 项目记忆的 `MEMORY.md`；项目说明（项目设置里） | `MEMORY.md` 每个线程开头都在；其它记忆文件只在被检索到时出现 |
| 本地 Claude Code（任何项目） | `~/.claude/CLAUDE.md`（全局）；仓库根目录的 `CLAUDE.md` | 全局那份是真正的「系统级」：换到别的项目也在 |
| Hermes | `~/.hermes/SOUL.md`；`~/.hermes/memories/MEMORY.md`、`USER.md`；工作目录里的 `AGENTS.md` | 记忆文件有字数上限，要短 |
| Codex | `~/.codex/AGENTS.md`（全局）；仓库的 `AGENTS.md` | |

所以要分两层放：
- **常驻层**：上面这些自动出现的地方。只放很短的「总指导」和最核心的几句原话，告诉 agent 去哪里经过其余的。
- **全集层**：`docs/思想总索引.md`（按主题，公开仓库）、`thought-index/_notes.md`（按时间，私有）、`推进方式/推进方式集.md`、项目记忆里的各个文件、原始会话。

常驻层一长就会被跳读，所以它必须短，满了就提炼，必要时推倒重写。〔原 10/24 22:24〕「甚至是重构，推倒等等都行」。

### 问 3：「思考的时候要经过它们」怎么做到？

〔AI 65%〕光放在眼前还不够，PROJECT-OVERVIEW 也在眼前过。要让「经过」变成一个动作，而且这个动作的结果看得见：

1. **常驻层里那几句，每次都会被读到**，这是最低限度的经过。
2. **总指导里加一问：「这件事以前想过吗？」** 提新想法、做判断之前，去思想总索引里按主题找：以前怎么说的，有没有被否掉，有没有张力。
3. **写出来的东西注明经过了哪几条。** 例如「经过：〔原 6/26〕让一切的尝试真正地尝试了；否决表第 3 条」。这样小林和后来的 agent 能看见这次思考到底有没有经过，经过了什么，漏了什么。〔AI 55%〕这一条最可能被嫌啰嗦，但它是唯一能检查「经过」有没有发生的办法。

### 问 4：为什么写成总指导，不写成规则？

〔AI 21:42，小林回「对的」〕「规则会变成禁令，总指导是一切推进方式的起点，而且是 Agent 自己问自己」。

所以常驻层里写的是一组问题，agent 自己问自己。三问是 21:39 那次定下的；我加了后三问，都是从小林 22:24 这条消息来的：

1. 我在哪里？
2. 这里有什么？
3. 对象是什么，要做什么，为了什么？我是从什么视角在看？
4. 这件事以前想过吗？（经过）
5. 刚才出现了什么有价值的东西？放到哪里，下一个才最容易看到？（记、放）
6. 这是不是重要的部分？是，就单独拎出来做好。

第 3 问里「我是从什么视角在看」是我加的〔AI 55%〕，来自〔原 10/24 22:24〕「但是这同样取决于视角，就像意图和目的甚至是热情之于创造一样」。我的读法：知道自己在哪，不是一个客观坐标；同一个地方，从不同意图、目的去看，「这里有什么」「什么重要」就不一样。所以问「在哪」时，要连自己的视角一起问。这只是我的读法，不是定义。

〔AI 50%〕第 4、5 问也是小林「历史复盘和对未来的预测和尝试是双向构建的」在一次推进里的样子：进来时经过历史（4），走之前把这次留给历史（5），中间是这一次尝试。

### 问 5：什么时候记？

**出现的时候就记，不等线程结束。** 线程会突然停（被关、被压缩上下文、容器回收），结束前才记，往往就来不及了〔AI 70%〕。

具体：
- 小林说了一句新的想法或纠正 → 当轮就写进项目记忆（对应主题的那个文件），标〔原 日期 地点〕。
- 一次推进结束或换方向 → 回头看一次：用了什么方式、坏在哪里、哪句是新的，补进推进方式集和思想总索引的「最近」那节。
- 常驻层定期提炼：新东西先进全集层；被反复用到、或小林确认过的，才进常驻层。

### 问 6：怎么防止记的时候弄错？

1. **标在每一句上**，见推进方式集第三节。
2. **小林消息里的句子，先查是不是 AI 说过的**（本文第一节就是这么查出来的）。
3. **记句子的同时记它在做什么**：定义、类比、举例、提问、顺口一提。〔原 10/24 08:22〕「我只是类比好吗」；〔原 10/24 21:12〕「我甚至都没说三种点」。
4. **问题不要记成决定。** 例如 05:35「你为什么是预测？」是一个问题，不是否决〔查，入口文档草稿〕。

### 问 7：「系统级记忆」指什么？

〔AI 70%〕小林说「放进系统级记忆里，或者什么东西」，意思是：不只这个项目，换到别的地方的 agent 也要有这个习惯。所以除了项目记忆和仓库，还要放进每种 agent 的全局文件（问 2 表里的 `~/.claude/CLAUDE.md`、Hermes 的 `SOUL.md`/记忆、`~/.codex/AGENTS.md`）。这些文件在小林电脑上，要通过远程会话去写，写之前先备份。

全局文件里不放 Cognos 的具体内容，只放总指导和小林几句跨项目的原话，再写一行「在 Cognos 里，思想在 docs/思想总索引.md」。〔AI 75%〕理由同入口文档草稿：「全局放结构，项目放内容」。
