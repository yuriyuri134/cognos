# Cognos v3 行动思想

这不是另一份总设计，也不是固定教义。它记录 Cognos 在真实施工、试用、失败、修正和复核中留下的**行动层认识**：哪些做法开始显出力量，哪些假设暴露了局限，哪些原则正在改变下一步怎么做。

项目过程本身也是认识材料。一次 bug、一次误判、一次 agent 分歧、一次真实试用、一次删除后反而更好的结果，都可以修改这里的认识。后续不应只更新“做了什么”，还要问：**这件事改变了我们怎样理解 Cognos，以及以后怎样行动？**

## 更新方式

每次重要 Packet、真实活动试用、架构删除/合并或连续性事故之后，都复核本文件。新的过程结晶可以：

- 新增一条暂定认识；
- 修订已有认识的适用范围；
- 用反例将它降级或撤回；
- 把原本只是工程习惯的东西提升为有证据支持的行动原则。

每条原则尽量保留四件事：**过程来路、当前认识、行动后果、可推翻条件**。工程通过并不自动使一条思想成立；思想成立也不替代工程验收。

---

## 1. 过程不是施工噪声，而是认识发生的地方

**过程来路**

多轮 Cognos 重构里，真正改变方向的往往不是先验架构图，而是运行中暴露出的差异：采用组合实际上没有压缩输入、独立 situation 会被 Formation 镜像覆盖、Tension 的 status-only 更新会擦掉旧正文、Working State 能恢复却可能已经过时。

**当前认识**

设计文档只表达我们以为系统会怎样工作；项目过程提供系统实际上怎样工作的反作用。二者发生冲突时，真实运行、原始记录和可复现结果优先。

**行动后果**

施工台账不只累计完成项。每轮都要提取“这次过程改变了什么认识”，并允许它反过来改下一批 Packet、协议甚至总设计。

**可推翻条件**

如果某类过程信息长期不能改变设计选择，只产生重复描述，就不应继续把它提升为行动思想。

## 2. 结构的价值在于改变后续活动，不在于它能描述自己

**过程来路**

Context Snapshot、Formation、Tension、provenance、fingerprint、history browse 等机制不断增强可追踪性，但“能证明发生过什么”并不等于“因此想得更好”。真实试用多次迫使我们把这两类证据拆开。

**当前认识**

一个认知结构最强的证据，不是它被记录、显示或引用，而是它使模型之后**接触了不同材料、拒绝了不合适经验、修改了构造、发现了反例，或因实际结果改变了方向**。

**行动后果**

新机制先问它改变哪一个可观察的后续行为。若只能增加说明字段、状态或审计信息，就把它明确归为 observability/provenance，不宣称认知增益。

**可推翻条件**

如果后来发现某种纯可追踪结构即使不进入模型输入，也稳定改善了人的协作和模型后续表现，应重新扩大“认知作用”的边界，但必须展示作用链。

## 3. 同一个事实尽量只有一次 replay

**过程来路**

Formation/Tension 一度被 Context、API、Service、UI 分别解释，`cognitive_conditions` 甚至会再次 replay 已经投影过的状态。结果是兼容逻辑泄漏到多层，`state.situation` 逐渐成为可能过时的镜像。

**当前认识**

事件可以有许多消费者，但一个事实不应有四套“当前状态”算法。当前方向是：

`run events + Activity state → canonical ActivityView → API / UI / model context`

ActivityView 是纯派生、可重建、不可写回的视图，不成为新的真相源。

**行动后果**

以后遇到“某层还需要再解释一下”的冲动，先检查是不是应该扩展唯一 replay 规则或消费同一派生视图，而不是再造一个 projection/cache。

**可推翻条件**

若不同消费者确实需要语义不同的视图，应显式说明差异来自不同任务，而不是悄悄各自重演同一事实。

## 4. 删除实验和消融优先于继续增加 Cognos 概念

**过程来路**

随着 `read_occurrence`、`browse_history`、`browse_experience`、`inspect_activities`、`import_activity` 等能力逐个增加，系统开始出现一种风险：每发现一个盲区，就再长出一种 operation 或状态层。

**当前认识**

复杂性不能因为“每一块单独都合理”就自动成立。真正需要证明的是：删掉某一层以后，关键能力是否下降。

**行动后果**

当前优先做 baseline / minimal / full 消融，而不是新增本体。特别比较：完整 Activity Protocol、Formation/Tension/cognitive conditions、experience candidate heuristic，以及中性 locate/read/import 能否替代多种浏览操作。

**可推翻条件**

若消融稳定出现只有完整结构才能完成的关键行为，并排除信息权限差与提示差异，该结构就获得更强的保留理由。

## 5. 协议和工具本身也会消耗认知

**过程来路**

Activity Protocol 从少量边界逐步长成一套操作语言；模型需要先理解 Cognos 怎样操作，才开始处理原任务。真实 Codex 两次进入试验又暴露了更基础的一层成本：模型已经生成可用的 Formation/Tension，却因为把 JSON 中的 `_`、`[`、`]` 写成 Markdown 转义、或用了近义状态字段，整轮在传输边界被丢弃。直到这些真实出现过的表面偏差被窄兼容并留下 repair 记录，认知内容才真正进入 Activity。

**当前认识**

帮助思考的结构如果要求模型持续花大量能力理解结构本身，就可能反过来挤占对材料和问题的注意力。认知基础设施不是免费的；协议的成本不仅是 token 和理解负担，也包括“有意义内容能否可靠穿过格式边界”。

**行动后果**

协议只保留少量核心不变量的方向必须被实际 A/B 测试；具体 operation 尽量通过 tool schema / 当前 affordance 按需暴露。对传输容错只接受真实出现、语义单一的窄修复，并显式记录 `transport_repairs`，不能靠宽松猜测把任意坏输出“修成正确答案”。评估时同时记录任务表现与 protocol/context token、无效调用、协议失败和修正调用。

**可推翻条件**

如果长协议在同模型同任务下稳定减少错误并提高任务结果，且收益超过成本，则保留相应部分，而不是为了“简洁”删除。

## 6. “过去被使用”不等于“现在值得使用”

**过程来路**

跨 Activity experience candidate 当前用“曾 adopted 或产生 actual result”作为最低代理变量。它适合启动，却天然可能把历史使用痕迹误当成当前相关性。

**当前认识**

经验的价值是处境关系，不是历史热度。旧构造既可能值得复用，也可能因为条件变化而成为最危险的诱饵。

**行动后果**

经验迁移实验必须同时放入：曾使用但当前错误、曾产生结果但条件已变、真正有用、从未采用但当前有价值的候选。系统不仅要会复用，还要会拒绝和越过自己的历史偏好。

**可推翻条件**

如果真实任务证明“有使用痕迹”在较大样本上是有效而低成本的发现信号，可以保留为 hint/filter，但仍不能升级为适用性判断。

## 7. 可恢复不等于仍然正确；连续性必须允许新现实覆盖旧状态

**过程来路**

Working State 最初解决 fresh session 丢失 live edge 的问题，但很快出现另一种失败：文件能完整恢复，objective 却已经落后于更新的用户指令。于是 continuity 从“能读回来”推进到 generation、原始 user-record anchor、stale 检测和 rollover binding。

**当前认识**

持久状态只是候选继续点，不是当前真相。新用户表达、真实工作树和外部结果始终可以使它失效。

**行动后果**

任何恢复层都要同时回答两件事：它有没有损坏；它还代表不代表现在。语义 Working State 继续接受 pointer-only 恢复方案的比较，不因已经实现就默认正确。

**可推翻条件**

如果多次 fresh-session 实验显示更轻的机械指针恢复同样可靠，应进一步削弱甚至移除持久语义 Working State。

## 8. 工程证据、认识证据、可追踪证据必须分开

**过程来路**

项目已经出现很多“测试全过但认知作用仍未证明”的情形。相反，真实模型活动也可能显示方向性价值，却不足以证明并发、幂等、来源和恢复正确。

**当前认识**

三类证据回答不同问题：

- 工程证据：程序是否按契约运行；
- 认识证据：结构是否改变了更好的后续判断和行动；
- 可追踪证据：我们能否知道结果从哪里来、怎样重放。

任何一类都不能替另一类补分。

**行动后果**

后续实验结果分层报告，不合成一个漂亮总分。尤其不能用更多 provenance 弥补任务能力没有改善，也不能用一次精彩模型输出替代工程正确性。

**可推翻条件**

这不是要永远割裂三者；若某机制建立了清晰因果链，可以描述它们怎样相互支持，但仍保留证据边界。

## 9. 兼容层必须有退场条件

**过程来路**

`state.situation` 的 Formation mirror、legacy envelope、旧字段适配最初保护迁移，但长期保留会让各层开始判断“哪个是真状态、哪个是兼容投影”。

**当前认识**

兼容不是第二套永久架构。兼容层如果没有明确退场条件，会逐渐成为新复杂性的来源。

**行动后果**

任何新增兼容桥都要同时记下：谁仍依赖它、迁移完成的判据、何时可以删除。当前 ActivityView 收敛完成后，应继续把 UI 和 API 的重复判断移向同一派生视图，再考虑停止 Formation mirror 写回。

**可推翻条件**

如果某个旧表示仍承担独立、真实且不可被新结构替代的用途，就应重新定义它的地位，而不是因为“旧”而机械删除。

## 10. 不等最终认识论完成才行动，但每次行动都要能反过来修改认识

**过程来路**

Cognos 一直处在哲学目标远大于局部实现的张力中。若等待完整主体理论再写代码，系统不会产生新的现实材料；若只做工程，又会把方便实现的对象误当成认识本体。

**当前认识**

行动和思想不是先后两阶段。更好的节奏是：提出暂定结构 → 让关系真实发生 → 面对结果 → 提取过程结晶 → 修订结构与思想。

**行动后果**

Packet 不再只问“完成了吗”，还问“它让什么以前只是猜测的东西变得可观察？它迫使我们改掉了什么？”；本文件随这些答案持续变化。

**可推翻条件**

如果某轮行动没有产生足以改变任何认识的新差异，就诚实记录为工程推进，不强行制造思想结论。

## 11. 比较认知组织时，先固定“可达世界”

**过程来路**

准备 baseline / minimal / full 消融时发现，如果 baseline 根本看不到 full 能读取的历史或材料，那么任何成功差异都可以被解释成“给的信息更多”，而不是 Cognos 的组织方式产生了作用。反过来，如果三组只是复制同一个长 prompt，也测不到结构本身的代价。

**当前认识**

认知结构的比较单位不是“提示词长得像不像”，而是：在同一个模型、同一个任务、同一个底层可恢复信息池和同一组真实操作能力下，不同组织方式怎样改变后续行为。即时呈现可以不同，但某组不能秘密拥有另一组永远无法取得的事实。

**行动后果**

消融 runner 把完整 Context Snapshot 与模型实际投影视图分开：证据层保存完整事实，prompt profile 只决定哪些组织进入模型。实验同时记录任务行为、tool/model calls 和 protocol/context 成本；不能用 provenance 更完整来替能力得分补分。

**可推翻条件**

如果未来证明某项 Cognos 能力的本质恰恰是改变“什么能够被发现或取得”，那么可达集合本身可以成为被测变量，但必须单独设实验，不与模型组织层的消融混在一起。

## 12. 并行不是免费的，审计质量不等于 agent 数量

**过程来路**

一次多角度审计同时占满 5 个 subagent 槽位，随后出现 thread limit、model capacity 和连续 stream disconnected；继续快速补开没有增加证据，反而制造了更多失败状态和施工噪声。主线程直接查代码、跑测试却仍能继续推进。

**当前认识**

并行 agent 是一种有外部容量、调度和会话连续性成本的工具。独立视角有价值，但数量本身不是独立性，也不是严谨性的代理变量。能由代码、测试和运行事实直接裁定的问题，增加 agent 常常只增加通信面。

**行动后果**

默认由主线程施工；只有真正独立且可能改变下一步的审计才开 subagent，通常最多一个。相关问题合并成一次任务；健康 agent 优先复用；capacity/stream failure 后先继续主线，不立刻成批重试。以后把“并行度”也视作实验和施工环境的一部分，而不是无限资源。

**可推翻条件**

如果后续平台在较高并发下长期稳定，而且多 agent 相比单主线程反复发现主线程遗漏的高价值缺陷，并且收益显著超过调度成本，可以提高并行度；仍应由证据而不是习惯决定。

## 13. 连续性只有重新进入人的行动时，才成为产品连续性

**过程来路**

Activity 的最近修订、Formation、Tension、Result 和 focus 早已能被保存并恢复，但返回项目的人仍需要自己判断“我上次到底停在哪里”。第二次进入测试暴露出一个差异：后端已经连续，人的行动界面却还没有连续。加入由现有 ActivityView 派生的“上次停在这里”后，只用 project URL 重进就能直接看见正在形成的内容与当前关注点，不需要再造一份摘要或记忆状态。随后真实两次进入又向前推了一步：第一次留下的 Formation/Tension 在第二次被同一稳定 ID 带回；新的“无人值守定时灯”事实使 Formation 被改写、Tension 被解决，下一 Move 转向核对定时规则。

**当前认识**

被保存的数据只是潜在连续性。只有当它在再次进入时重新成为人的可见处境、可继续动作和下一步判断的一部分，连续性才真正进入产品。连续性因此至少有三道门：**恢复得到、用户看得见、后续行为真的用得上且能被新现实改写。**其中任何一层断掉，保存得再完整也只是档案连续，而不是活动连续。

**行动后果**

以后增加任何 continuity / memory / state 机制，都先检查它怎样回到人的下一次行动；优先从现有事实机械派生继续点，避免为了“记住”再制造一份需要同步的新真相源。验收从“状态存在”推进到“第二次进入能否继续”，再推进到“新现实出现后，旧状态能否被修订而不是机械延续”。一次成功实例只说明这条作用链已经真实发生过，下一阶段要问它是否在不同任务和不同 prompt profile 下稳定发生。

**可推翻条件**

如果真实使用表明明确的返回点并不降低恢复成本、用户仍需要重新叙述大量背景，或者机械派生经常把人带回错误位置，就应重新设计接续方式；这条原则不意味着界面上必须永远存在一个固定的“上次停在这里”模块。

## 当前优先验证的思想，而不是继续扩写的思想

截至当前阶段，最值得用实际任务继续压测的是：

1. canonical ActivityView 是否真能让“一个事实只 replay 一次”，并最终删去重复 compatibility interpretation；
2. minimal protocol 是否在不损失关键能力的情况下比 full protocol 更轻；
3. Formation/Tension/cognitive conditions 是否在真实任务里改变了材料选择、反例发现和经验拒绝，而不只是更可追踪；
4. `browse_experience` 的使用痕迹 heuristic 是否帮助迁移，还是把系统吸向过去；
5. semantic Working State 相比 pointer-only continuation 是否真的减少 fresh-session 错误。
6. baseline / minimal / full 是否能在相同可达信息池下产生稳定、可重复的行为差异，并且收益大于 protocol/context 成本。
7. 已有一例真实 Codex 第二次进入出现“旧 Formation 修订 + 旧 Tension resolved + 下一 Move 换向”；现在要验证这种行为是否跨任务重复，并在 baseline / minimal / full 同可达世界下区分“模型本身会修订”与“Cognos 结构确实改变了行为”。

这些不是新模块，而是一组可以让现有思想被证实、缩小或推翻的实验方向。
