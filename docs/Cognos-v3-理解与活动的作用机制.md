# 理解与活动的作用机制

2026-09-20。状态：结合最新聊天与当前代码的实施设计；没有把候选理论宣布为已实现能力。

## 目标与分工

目标继续是帮助 AI 更好地思考、认识，并使活动经验改变以后怎样思考。当前外部架构承载模型、人与材料之间的持续作用；不声称已经解释模型内部如何产生理解。

模型贡献理解、重表述、生成与选择。程序贡献可执行操作、来源与版本、实际结果、可恢复的状态和可修改的组织。人贡献关切、纠正、判断及真实活动。三者的作用都须保留，不能将模型输出改名为系统新增的能力。

认知操作不预先穷举。比较、构造、并置、询问可以出现，但不成为每轮必经步骤。暂停、直接回答与继续执行都是可能的适当行为。

## 代码现实

- activity_service 已允许模型提出操作，由程序执行，再把实际结果交回模型。
- 活动材料既可保存文本，也可保存可执行组合。adopt 改变当前材料展开方式，adopt_source 改变项目取材方式。仅修改定义而不采用，不改变当前执行。
- context_assembly 从采用的组合取得实际读取材料；多个 Formation 与未解决内容进入上下文。
- 后续核对发现：组合即使只截取局部，active_materials.entries 仍重新注入其依赖全文。已修复为采用组合时保留版本来源与明确回读操作，正文以 compiled 结果为准；未采用时仍提供全部材料。当前用户输入和实际结果保持独立进入，不受组合裁剪。此变化只控制 Activity 自动组装，不宣称清除了模型在其他位置或先前调用中接触过的文字。
- Formation 的 active/dormant 已能改变当前投影，但历史文字仍可能出现在标记过的其他材料中。停用不能宣称模型彻底遗忘。
- 外部 retrieve 接收模型提出的查询并保存来源；多个查询仍可能围绕同一个错误假设。查询数量不代表探索广度。
- 项目取材按关键词返回最长 6,000 字节选。原文虽完整保留，但之前活动缺少继续回读未见区间的操作。
- cognitive_runtime 的 reopening_channels 是能力说明，不是自动发现反例的机制。condition_fingerprint 是输入校验，不能证明认识变化。

## 一、形成怎样获得实际后果

采用现有的“表达—提议—执行”边界，不新增认知调度器。

1. 模型可以提出多个读法，也可以没有读法。读法的来源引用保留，不视为用户承诺。
2. 当它认为某个读法需要影响活动时，提出具体操作。例如读取另一份材料、修改并采用一种材料组合、构造可计算实例、改变项目取材表达式。
3. 程序验证引用、版本与操作参数。执行成功后，当前实际材料或采用方式发生变化；失败作为结果保留，不预写成功。
4. 下一次调用从已改变的活动重建输入，而不只附加一句“请考虑这个读法”。
5. 模型可以依据新材料修订理解，也可以保持原状。是否更好需结合内容判断，不能用修订次数代替。

第一版重点复用已经存在的材料组合和取材定义。需要核对模型是否能清楚发现、读取、修订与停用这些定义，以及界面能否展示它们真实改变了什么。若操作过于繁琐，应改善直接操作入口，不新增一套同义结构。

## 二、当前理解不能垄断重新接触

至少保留以下不同通路，不能全部交给一个基于当前理解的相关性排序：

- 用户新输入进入本轮，不经过旧理解的相关性过滤。
- 原始材料目录仍可见，可按版本直接读取未采用材料。
- 已知原始发生可以直接按 ID 回读，不要求再次命中旧关键词。
- 实际工具失败和结果继续进入活动，不因“不符合预期”而静默丢弃。
- 用户和模型都能改用另一种材料组合；旧组合保留，可恢复。

本轮新增 read_occurrence 操作：只读当前项目的原始记录正文，使用字符区间与 next_start 分页。返回来源、作者、总长度、区间与截断状态，保存为不可变活动材料。它不修改现有取材定义，不自动替换当前理解。

这解决“已知道某条原话存在，却读不到其余内容”的断点。尚未解决“根本不知道漏掉了哪条材料”：后续需要为项目取材增加可浏览的结果范围和继续取材路径，再研究基于原始表达、不同读法及新结果的多种检索。不要为了表面开放随机塞入大量历史。

## 三、经历怎样影响后续活动

不立即自动沉积“有效策略”，也不把旧模型自评当作成功依据。

第一步允许把真实活动中的材料组合、构造程序和取材方式带入另一个活动，保留：

- 使用过的版本及原材料来源；
- 在什么情形下采用；
- 实际产生的结果，包括失败与未解决内容；
- 谁认为它有帮助，这个判断的依据与限制。

带入后应是可检查、可修改的候选；显式采用后才改变当前展开方式。第二个活动可以修订它，不能反向改写第一个活动的发生史。

随后再考虑怎样推荐这些候选。推荐规则也须可停用；没有证据时不自动提高全局优先级。自动选择、可学习的检索策略、模型训练都是后续可能路线，不预定其中一条是认知发展的唯一途径。

## 四、连续活动中的具体推演

学习：从实际学习文本开始，模型可能提出“通过作用理解对象”的读法。它构造可计算的例子，程序生成实际结果。遇到例子不支持读法时，允许限制其适用范围、换表示或停留。新活动可以重用这个构造方式，但不预设一定有用。

开放处境：用户同时提到钱与数学。保留原话及不同解释，不预置“先赚钱”或“先追问”的固定策略。后续回读发现原话中“目前生活有保障”被遗漏时，这条内容可以直接进入，原取材方式不再成为门槛。如何调整方向由对真实内容的判断决定。

创作：允许直接并置、续写并产生新作品；不要求先生成理解。作品再次进入材料，可能改变下一次写作方式，也可以暂时没有解释。不要以是否出现 Formation 衡量创作是否发生。

## 五、施工顺序与交付证据

2026-09-21 实施补充：evaluate 成功后，程序直接把实际 value 保存为不可变 JSON 材料并返回 document ID；表达式、实际读取版本、执行前活动版本和请求发生 ID 保存在追加式原始计算记录中。后续组合可直接 read/select 这份值，不需模型重写。修改原输入不改变旧结果；采用方式不自动转向新结果。计算失败不创建成功结果材料。此项实现的是活动内复用，跨活动带入与选择机制仍未完成。

1. 补原始记录分段回读。检查长原文可连续重建、项目边界、原始记录只追加、结果进入下一调用、重复请求不重复写入。
2. 检查并改善“理解 → 修改采用方式 → 实际输入改变”的真实使用路径，复用已有组合能力。明确展示当前采用版本及影响的材料，而非只展示模型解释。
3. 在一段真实学习活动中把构造、实际结果与理解修订连起来。内容由实际参与者产生，不在程序测试里预置“更深理解”然后宣称模型变强。
4. 补未知遗漏的发现与继续取材能力。评价搜索时检查范围、正文、未读部分和问题变化，避免只看链接数量。
5. 将一项实际使用过的构造或组织方式带入另一活动，检查可修订性、来源与适用范围。完成后才讨论自动推荐。

程序测试证明边界和执行正确；真实活动证明内容如何展开；适当对照帮助判断系统增益。三者不能互相替代。一次性长提示对照需要说明材料、调用预算与工具机会的差异，不作为单独的项目成败门槛。

此设计仍未解决通用探索策略、未知遗漏的识别、长期认知发展，也不规定主体的最终结构。下一步必须继续补这些机制，而非把上述有限能力重新定义成完整目标。
