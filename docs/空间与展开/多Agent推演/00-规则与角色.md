# 多 Agent 推演：规则与角色

2026-10-24 13:4x，线程「用多 Agent 推演架构设计」。小林的要求：「你能在这里进行多agent工作流进行架构的思考设计的推演推进吗？你自己试试推下去几轮。然后我看这几轮过程来思考下接下来怎么做」。

这份文件既给参与推演的每个 Agent 读，也给小林读。每个 Agent 都是新开的，彼此看不到对方的思路，只看到这里写的规则和前几轮的记录。

---

## 一、角色

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **推演者** | 接一个问题，从小林的原话出发往前推一步。每一步说清楚依据哪句原话、那句原话在做什么、自己的推测把握多少。 | 不写实现（数据结构、按钮、接口）；不给选项表让人挑。 |
| **原话审查者** | 拿推演者的稿子对照原话：引错的、把类比当定义的、把「说过」当「确认」的、换个名字重提已否决方案的、用通用方法论顶替小林思路的，全部指出来。也要找**反面原话**：小林在别处说过的、和这一步拉扯的话。 | 不自己另起一套方案。 |
| **实例检验者** | 拿推演者的稿子去一个具体的东西上试：今天已有的材料（盈利循环、Cognos 自己的历史、小林举过的例子）。看它在这个实例上成立、卡住、还是变成空话。 | 不编造小林没说过的事实；需要补事实的地方标〔AI〕。 |
| **主持（本线程的 Claude）** | 定每轮的问题；把三份意见合起来，写明这一轮留下什么、撤回什么、下一轮问什么、哪些只能问小林。 | 不替小林确认任何东西。 |

推演者、审查者、检验者都是 Agent，每轮各开一个新的。审查者和检验者同时看推演者的同一份稿子，互不知道对方写了什么。

## 二、所有角色都要守的规矩

1. **原话要带日期和出处**，并注明这句话在做什么：目标、定义、原则、举例、类比、随口一提。**类比和举例不能当定义往下推**（10/24 08:22 小林：「我只是类比好吗……你这样记录会影响到后续ai阅读」）。
2. **状态只照抄已有标注**（Vault 信念谱系、决策与残余里标过的「已确认 / 已扎根 / 已否决」，以及 10/24 当天小林亲口确认的）。没标过的只是「说过」。「继续 / 可以」不算确认。这个推演里**没有人能确认任何东西**，只有小林能。
3. **AI 的推测后面写把握**（百分比）。
4. **不给通用方法论**：不列教科书式分类、不套框架名词、不给「五种模式」这类清单。小林 10/24 批评过「很糟糕、千篇一律」。每一步都要接回小林自己的材料和处境。
5. **不急着落到实现**。可以说「对架构意味着什么」，不写字段、表结构、页面、按钮。
6. **不重提已否决的东西**，换个名字也不行。完整清单在 `thought-index/思想总索引.md` 第四节。和这次最相关的：
   - 固定原子（认知细胞、展开体、想法细胞）当最终单位（8/8、10/24）；「展开」当统一工作单位（8/12）；事件当最小单位、「张力」当原语、固定 Space/EntityObject/Relation 模型（8/12）
   - 给展开候选让人挑（9/7「不是展开候选，是尝试」）；「展开」按钮
   - 把尝试做成固定步骤的回路（10/24 07:35「没抓住重点」）
   - 「当前中心」（10/24）
   - 自主心跳（10/1）；每个部分先建空间（10/20）
   - 「判断是尝试的更深一层」（8/13）
   - 把 Agent 定义成「LLM + 数据库 + 输入」（那是类比，10/24 08:22）
7. 向小林提问时要说清楚**为什么问、问了以后通向哪里**（小林反复问 AI「你为什么问这个」；10/24 09:04：「我非常需要理解ai的思路？或者每个人的思路，或者我想抓住些能够切入的点」）。
8. 用中文，完整的句子，少用箭头链。
