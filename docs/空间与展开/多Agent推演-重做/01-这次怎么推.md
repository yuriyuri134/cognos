## 一、这次服务哪一个目的

〔原 6/18，10/24 再说〕「我想让ai学会真正的思考，或者像我一样能够思考」。

具体落在 13:19 这一句上：〔原 10/24 13:19〕「空间内，一个对象的展开方式是丰富多样的……这样ai就能更加深入地认识各个对象，和主体，以及世界」。

这次要看的是〔AI 70%〕：
1. AI 能不能对**一个真实对象**（盈利循环），**真的**用好几种方式展开它；
2. 几种展开放到一起之后，能不能互相改动、长出单独一种做不出的东西；
3. 架构该是什么样，从这次真实发生的过程里读出来，不从概念里推。

## 三、三轮的计划（这次的计划，不是流程）

〔原 10/24 07:35〕否掉过把尝试做成固定步骤的回路。下面只是这一次怎么排，做的时候看情况改。

### 第 1 轮：各自展开，互不相见

五个 Agent 同时开，各用一种方式展开盈利循环。五种方式都出自小林自己的话，不是我编的分类：

| 代号 | 展开方式 | 出自 |
|---|---|---|
| A | 结构展开，再跳到经济学、学术领域 | 〔原 10/24 13:19〕「先认识这个对象的结构可以怎么展开，盈利模式，展开为，经济循环，内部再进行细化分。然后可以跳跃……往经济学展开，学术领域展开」 |
| B | 数学建模，在模型上模拟 | 〔原 13:19〕「数学建模展开」；〔原 10/24 08:34〕「这些构造的模型就可以作为各个基础单位或者进行实验对象进行模拟了」 |
| C | 现实实例展开 | 〔原 13:19〕「还可以进行现实实例展开」 |
| D | 直接把握，以及幻觉的尝试 | 〔原 9/28〕「也可以进行简约的、直接地把握，也就是判断或者直觉跳跃」；〔原 6/7〕「幻觉的尝试」 |
| E | 可视化 | 〔原 13:19〕「还可以进行可视化」；〔原 10/24 08:34〕「建模，可视化，显现，可追踪追溯」 |

另外一个审查 Agent F，等五份都交了再开，五份一起看。

13:19 里的「实验展开」没有单独给一个 Agent〔AI 60%〕：
- B 在模型上做的就是一种实验；
- 碰现实的实验要小林自己去做。〔原 5/19〕「实验就是直接在创业里实践啊，不需要额外实验」
- 哪个 Agent 想到能碰现实的实验，就写下来，并且先自己答「做了会碰到什么」。

### 第 2 轮：互相看见，再展开

- 把五份稿子和审查意见，发回给第 1 轮的同一批 Agent。
- 每个 Agent 看完别人的，用自己的方式接着做：重跑模型，重画图，再检索，或者推翻自己。
- 每个 Agent 都写清楚：别人的哪一处改了我的哪一处，为什么。没改的也写为什么。
- 想看的是〔原 10/24 13:10〕说的那种事情会不会发生：「再组织到了一定程度，各个部分联动满足了某种体系的条件，从而发生一些想不到的效果，或者能力的飞跃」。不强求，没发生就照实写没发生。

### 第 3 轮：从发生里读架构

- 开一个新的 Agent，读前两轮的全部原稿，加上主持的过程记录。
- 它要读出来的是：
  - 这次展开**实际**是怎么发生的；
  - 要发生它，得有什么在场；
  - 东西在 Agent 之间是怎么走的，哪里丢了；
  - 要让这种事对任何对象、在小林和 AI 之间都能发生，而且不丢，Cognos 需要是什么样。
- 要经过入口文档线程的结论、读法引擎、08:34 的填充 / 建模 / 映射与构造。
- 再审查一次。
- 不写实现。

## 四、每个 Agent 都要守的规矩

1. **先读这些**，再动手：
   - `/home/claude/cognos/PROJECT-OVERVIEW.md`
   - `/mnt/project-files/thought-index/思想总索引.md` 的「〇、每次都要经过的」，第四节否决表，第五节张力，第三节 14「组织与盈利」
   - `/mnt/project-files/space-expansion/项目核心点与结构展开.md` 第一部分第 1 节「目的」，第二部分开头 13:19 原话
   - 本文件和 `00-主持定位-先答六问.md`
2. **稿子开头先答总指导**，5–10 行，不用全答：
   - 我在哪：哪次推演、第几轮、我是谁；
   - 手边有什么；
   - 对象、目的，我从哪个主体、什么视角展开；
   - 以前想过吗：经过了哪几条，写出来。
3. **真做。**
   - 建模要有能跑的代码和跑出来的结果；
   - 检索要给链接；
   - 画图要给出图。
   - 不交提纲，不写「可以考虑」「未来可以」。
4. **每一句标来源**，标记跟着句子走：〔原 日期 出处〕〔世 出处〕〔AI xx%〕〔AI 转述〕〔查〕。小林常把 AI 的话贴回对话里，贴回的部分不算原话。
5. **不给通用方法论清单。**
   - 借来的每一个结构，经济学的也好、别的领域的也好，都要拿去顶小林的话：哪里对上了，哪里对不上，对不上的那一处说明了什么。
   - 〔原 10/24〕批评过这种做法「很糟糕、千篇一律」。
6. **类比和举例不当定义往下推。** 〔原 10/24 08:22〕「我只是类比好吗……你这样记录会影响到后续ai阅读」
7. **不重提已否决的**，换个名字也不行。清单在总索引第四节。
8. **不出「是 A 还是 B」去给小林的抽象词消歧。** 〔原 10/24 21:12〕「讲一些抽象概念不讲清楚具体定义就是为了刻意保留模糊……要的不是精准而是更多的可能」
9. **可以提议，要敢于尝试。** 〔原 10/24 21:12〕「可以提议，要敢于尝试，但是纠正和判断不能少」。提议时写出把握，以及可能错在哪。
10. **要问小林的，先自己答。** 带着自己的回答去问，写明为什么问、问了以后通向哪里。
11. **对象是盈利循环，也就是一个组织的经济系统。**
    - 不是「小林个人怎么有收入」，也不是这个工作流本身。
    - 主体空间（小林，未来的成员，组织）要碰，但它是三个空间之一，不是对象本身。
12. **安全。** 摘录里不该有密钥。万一在任何材料里看到 key、token、密码，不要抄，不要转述。
13. **写文件。** 只有 B 和 E 往 `/mnt/project-files/space-expansion/多Agent推演-重做/附件/` 里写代码和图，其他人不写项目文件夹。稿子本身就是你最后回复的全文，主持会原样存档。
14. **用中文，完整的句子，少用箭头链。**
