# 活动组织初版：开发规格

作者：Codex。更新：2026-09-11。地位：总设计 v0.1 的候选实现，未被认领为完整认识架构。设计来路见《Cognos-总设计-v0.1-2026-09-10.md》，交付状态见《Cognos-实施进展-2026-09-11.md》。

## 目标与范围

在现有项目内新增可以持续编辑、继续使用的活动。材料、作品和当前采用的组织方式都可在活动中被重新面对。组织方式实际生成下一次模型输入，而非只作为报告里的建议。

第一版以文本和 JSON 为载体，以读取、选择、组合、文本变换和计算承载可以确定执行的部分。模型与人负责语义解释和提出新组织。此边界不代表世界只有这些类型，也不宣称初版自行产生一般理解。

原始输入可以没有问题或目标；当前关注可以形成、改变或为空。原始用户话语与当前关注分开保存。

## 当前采用的组织方式

一份普通 JSON 文档可以表达一个组合过程。文档先作为可编辑内容存在；显式采用某个版本后，它才用于组织当前活动的后续输入。修改该文档形成新版本，不静默改变已采用的版本；再次采用新版本才改变运行。

采用时同时固定被调用的组合定义版本；普通材料读取未指定版本时，读取本次快照中的最新版。因此改材料会影响下一次结果，改组合定义需要再次采用。界面分别显示编辑版本和采用版本。

组合过程允许：读取活动内文档的指定版本或此次快照中的最新版；选择结构化内容中的位置；切片；组合文字或结构化值；替换文字；执行基本计算；调用另一份组合定义。调用不能形成无限递归。没有任意 eval 或 shell 执行。

读取、组合和计算产生的是实际结果。编译失败显示具体失败，不伪装为完成，也不静默回退到旧组织。新的表达能力通过后续新增操作实现接入；当前有限操作集是明确的实现限制。

活动始终保留全部材料的目录和读取入口。已采用组织决定本次默认展开的内容，不删除未选材料，也不限制参与者请求重读它们。

## 保存与并发

新增独立 SQLite 存储，不替代第一发生场、组织数据或 runtime 状态。活动的修改以不可覆盖的修订保存，包含执行者、原因和当前状态。初版使用完整快照，优先保证语义简单、可回读；大规模材料去重不是这一步的工作。

文档分为保留原文的材料和可编辑的构造，二者是写入契约，不是认识类型。材料原文不能修改；可从它建立新的可编辑文档。每份文档的旧版本继续可读。停用一种组织只改变采用关系，原材料和旧解释不删除。

所有修改请求携带所依据的活动修订。事务中核对当前修订，失配返回冲突，不覆盖并发变化。一个请求的操作整批成功或整批失败。模型调用期间不持有数据库事务；调用结束后仍以输入时的修订提交。

## 模型与真实操作

复用原参与者 runtime 和串行调用约束。一次用户发起的继续活动只面向其选定参与者；允许为执行请求和返回结果进行有限次续接，不安排自主多模型对吐。

每次输入包含：本次用户发言、当前关注、全部材料目录、实际采用的定义、该定义产生的内容、执行失败或返回结果，以及必要的项目处境。原始发言不由可改写组织过滤掉。

模型可以提出文档修改、采用或停用组织、改变当前关注、读取其他文档、执行一个局部组合。服务负责真正执行并把结果交回；模型在文本中说“已经采用”不产生采用事实。

每次模型回复都进入原始发生，实际操作结果单独记录，避免把模型请求当执行完成。预算耗尽、协议错误、执行失败、正常暂停与等待外部结果分开表示。达到一次调用上限后，由用户继续；已经执行的操作不重放。

跨重启承接活动当前状态；各模型的既有 session 文件继续独立。更换模型不宣称主体连续性已经证明。

## 接入位置

- 新活动存储与组合执行不依赖现有 Inquiry 的必填 question；现有探究保持兼容。
- FastAPI 挂载项目下的活动创建、列举、读取、修订、输入预览和继续接口；继续服务通过现有 Participant 发出输入并写入原始发生。
- 项目界面新增活动入口。活动内展示材料与作品、当前采用的组织、继续对话；编辑与采用分开，初版提供可视的组合和预览，技术 JSON 放进高级编辑。
- 当前外部执行沿用 Handoff/DSH。执行结果应能作为带真实来源的材料回到活动；新组合解释器不直接执行任意外部命令。

## 学习与创作两条贯通路径

学习：加入含部分与整体数量的材料，形成计算与比较的组合，在不同材料上实际计算；发现参照不同后修订比较依据，采用新版本，后续输入实际改变。已知数学概念仍由人或模型贡献。

创作：从没有正式问题的文字开始，试写可编辑段落；采用一种并置、重排或替换组织；结果促使改写组织；再次进入时承接作品及当前采用方式。不要求填写失败或收获，也不自动制造一条“尝试事件”。

来源重读作为第三条核对：摘要与原话分别保留，切换取得和并置办法，修改当前采用的解释；它不能代替前两条成为唯一产品。

## 验收与未完成范围

必须检查：空关注可进入；来源不可覆盖；新版本不偷换已采用版本；实际采用改变结果；未选材料可重读；停用后材料仍在；组合失败不算完成；并发冲突不丢失内容；恢复后使用正确版本；模型请求与真实操作结果分别保存。

这些检查只证明运行契约。重要差异的发现、语义理解、审美判断与主体形成仍需内容分析。第一版完成也不意味着总计划的长期发展阶段完成。

## 已实现的接口与边界

| 接口 | 实际作用 |
|---|---|
| GET / POST `/api/projects/{project_id}/activities` | 列举、创建活动；标题可省略，不要求问题。 |
| GET `/api/activities/{id}` | 读取当前或指定修订、修订目录、运行及发言。 |
| GET `/api/activities/{id}/documents/{document}` | 按指定或最新版本重读材料，返回来源与修改者。 |
| GET `/api/activities/{id}/preview` | 实际执行当前采用的定义，返回内容、读取版本或具体失败。 |
| POST `/api/activities/{id}/changes` | 按预期修订提交一批修改；冲突返回 409，无部分提交。 |
| POST `/api/activities/{id}/imports` | 用真实发生标识引入正文，保留原作者；导入者与原作者分开。 |
| POST `/api/activities/{id}/continue` | 用请求标识续接选定模型；同一请求重试返回原结果，不重复执行。 |

原文与解释存于活动快照，模型原始回复另行追加到发生场，操作结果另留回执。运行中的输入快照和操作进度存在活动运行记录中；运行记录可更新，不冒充不可改写的原始历史。数据库与发生场之间没有跨文件事务；进程在两次写入之间退出时，可能留下尚无应用结果的原始请求。恢复不自动重放它。

当前一次继续最多调用模型 4 次，每次至多 20 条命令；一条修改命令包含至多 40 项操作。组合最多 2048 步、嵌套 32 层、单次结果 20 万字符；活动至多 100 份文档，单份正文序列化后至多 20 万字符，完整快照至多 400 万字符。达到边界明确返回失败，需要拆分或后续扩展；不会静默删掉旧内容。

初版按单个应用进程使用，同一进程复用参与者串行锁，不支持多个服务进程同时驱动同一 runtime。活动之间没有自动知识迁移，没有自动查遍 Vault，没有任意代码自修改。组合操作集的新增仍由实现者承担。

界面 `/activities` 提供活动改名、原文与草稿、引用已有项目发言或结果、材料排序组合、实际预览、保存预览、编辑与采用分离、停用、历史回看和继续活动。图片、音频等载体尚未进入这条新活动通路。
