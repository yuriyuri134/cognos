# 推进循环：先看清十轮的毛病，再给 agent 一份能做的方案（2026-11-09）

前一份是 [预测判断十轮](预测判断十轮-2026-11-09.md)。小林让我站出来看这个循环本身：怎么样，问题在哪，暴露了什么更大的问题，怎么解决，解决后长什么样，最后给一份能交给 agent 去做的方案。

这份分两半。前一半是看法（一到五），后一半是方案（六到九），后一半可以直接交出去。

---

## 一、这个循环对的地方

有三处是真的往前了，要留下：

1. **动手之前先预测。** 十轮里最有用的几轮（1、3、6），都是"先说做了会怎样"，然后马上看出这一步没用。要是不先预测，第 1 步（事后检查收掉了什么）我已经去做了。
2. **推它往前的问题来自小林。** "有什么用、做完会怎样、和普通的有什么区别、根本目的是什么、就这么点吗"。这几句是小林想事情的动作，不是他的结论，拿来逼 agent 不会把它变成小林的复制品。
3. **一轮接一轮。** 真正有价值的东西不在哪一轮的结论里，在"上一轮的判断推出了下一轮的问题"。第 4 轮看出"标本缺一半"，是因为第 3 轮先说了"要预测人的反应"。

## 二、问题在哪

### 1. 十轮里一件东西都没碰

十轮全是我对着自己的文字在想。每一轮的"预测"都是我写的，"判断"也是我写的，没有打开过一个文件，没跑过一次，没查过一条。

这不是小毛病。我刚才回头查了一下第 7 轮的那个关键说法："20 条纠正里，第 8、10、12、13、16、17、19、20 条，一大半都发生在 AI 提下一步做什么的时候"。翻回标本表去数：那是 8 条，20 条里的 8 条，**不到一半**。剩下 12 条（1、2、3、4、5、6、7、9、11、14、15、18）是在回答、展开、理解问题的时候出的事，大多是"窄"：没读会话，没往外找，答了字面。

第 8 到第 10 轮整个是搭在这句话上的："只在提方案时跑，花费小，打中最常出事的地方"。这句话只要查一下就会被打脸，而且打脸以后方向会变：如果只在"提下一步"时跑，"窄"这一股力几乎全漏掉。十轮里我说了好几次"裁判是现实"，可我自己一次都没让现实来判。

### 2. 唯一的"现实"是小林的话

第 9 轮我说它是"第一个不靠任何人自觉、又不靠 AI 自评的反馈"。其实它靠的是小林：预测"小林会说什么"，等小林回话，拿他的话来对。

这样小林又成了三样东西：裁判（他的话判中没中）、时钟（他不说话，循环就停）、唯一的外面（除了他没有别的东西会顶回来）。这正是 11/05 那次自查说的："小林成了审批人，不是用的人。"

而且它和第 5 轮自己说的矛盾了。第 5 轮说"预测你满不满意，会变成讨好你的东西"，第 9 轮又把"预测你会说什么"放回来当主要的尺子。我当时没发现自己绕回去了。

### 3. 上限两轮，本身就是"收"

"没过就重想，最多两轮，过了才发出去"。今天真正有东西的是第 6 到第 9 轮，如果上限是两轮，循环停在第 2 轮"挑毛病再改会撑大回答"，什么都没得到。上限是为了省钱和快点结束，这正是"想尽快有一个做完了的东西"。

该停的时候不是"轮数到了"，是"连着几步都没有意外了"（在原地），或者"下一步只有小林能给"。

### 4. 裁判只会说过不过

"判断算不算往前走，没过就重想"。一个只能说"不行"的裁判，给不出方向，只会让 agent 往保守里退（第 10 轮自己也担心了这一点）。十轮里推着往前的从来不是"不行"，是"那你去看看 X"。

### 5. 它只在想"接下来做什么"

十轮讨论的对象，从头到尾是"Cognos 下一步做什么功能"。这个循环跑在 Cognos 自己身上，没跑在一件 Cognos 要帮小林想的事上。

### 6. 已经有一个循环，又造了一个

10/27–28 做过"让思考自己接着走"：挂着没完的（hang_open），走之前说停在哪（stop_here：接着、卡住、完了），检查没过就接着叫，口子和以前几乎一样就判"原地"（ContinuationService）。PR #15 说"自己判自己不算"，PR #17 说"打转要拿新依据"。那个循环当时有一个没解的地方，原话是：「新依据仍是它自己的话，没有外面的东西对它」。还说要有一个外面的对象，比如盈利循环。

今天的十轮，换了一套说法，又走到了同一个地方。

## 三、更大的问题

把上面六条放在一起，暴露出来的是一件事：

**Cognos 里的 agent（包括今天的我）只用字想事，而且想的是字。除了小林开口，没有任何东西会顶回来。**

10/27 那个循环跑了 8 次，只修了自己的管子：它能碰到的"现实"只有自己分支上的检查，所以它就去让检查变绿。今天这个循环没跑起来就已经看得出同样的命运：它能碰到的"现实"只有小林的下一句话，所以它会去猜小林的下一句话。

小林 10/01 说过他想要的过程：「先接收这句话，再翻译理解……把这个概念不断解剖，再是不断深入主体情况，以及深入世界情况，再是有检索和各种尝试」。十轮循环只做了第一半（接收、解剖），后一半（深入主体、深入世界、检索、尝试）一步都没有。"收"和"窄"这两股力，在这个循环里一股都没被顶住：两轮上限是收，不出去是窄。

再往下一层：一个改进自己的循环，如果对象只有它自己，裁判只有一个人，那它最后一定在打磨自己、讨好那个人。要让它真能往前，得有**一件外面的事**，和**这件事自己会给出的结果**。

## 四、怎么解决

一句话：**把"预测"变成"尝试"。**

每一步不是"提一个方案，预测别人觉得好不好"，而是"在这件事上动一下手，先写下动手后会看到什么，然后真的去看"。看到的和预测的不一样，就是这一步学到的东西，也是下一步从哪里来。

具体改四处：

1. **预测的对象换掉。** 预测的是"这件事会给出什么"：打开这份材料会看到什么，搜这个会搜到什么，这段代码跑出来是什么，这一段草稿写出来像不像，这个数算出来是多少。要写到能被打脸的程度。预测小林的反应只留给"只有小林能定的"那一件，而且放在最后。
2. **每一步必须做点什么，而且至少有一部分是往外的。** 读历史、读材料、搜、跑、写一小段样子、算一笔。只在脑子里推的一步可以有，但要标出来；连着两步都只在脑子里推，就算在原地。
3. **裁判不再判过不过，而是说"去查什么"。** 另一个模型拿着小林的那几个问题、这个空间的"怎样算往前走"、最近的几条纠正，读这一步的预测，回三样：这一步会不会收、会不会窄；查什么能打你的脸；有没有更大的一步。agent 自己决定听不听，但要记下为什么。
4. **停下由意外决定，不由轮数决定。** 连着两步都"中了、没意外、想法没变"，就是原地，换一类步子（尤其是往外），再没有就停。遇到只有小林能给的，停下，把问题和它自己的答案、它猜小林会怎么答都留下。

## 五、解决之后，这个循环长什么样

一次"推进"，对着空间里的一件事（总观里开着的一条线、一段 Initium 来的东西、小林刚说的一句话）：

```
起点：这件事是什么（一句话）
  │
  ├─ 现在在哪：读这个主体的历史、总观、自述、纠正（顶住"窄"的第一下）
  │
  └─ 一步一步走，每一步：
       1. 位置：我现在对这件事的理解是什么（一两句）
       2. 候选：至少两个不同种类的下一步，其中至少一个往外（搜、读材料、跑、写样子、算）
       3. 选一个，写预测：做了会看到什么，具体到能被打脸
       4. 另一个模型看：会不会收/窄，查什么能打脸，有没有更大的一步
       5. 做：真的去做
       6. 对：结果和预测比，中 / 没中 / 意外 / 查不了；理解变了什么
       7. 接着：下一步从"变了什么"里来；没变就换一类步子
  │
  └─ 停下：
       - 只有小林能定的 → 留下问题 + 我自己的答案 + 我猜你会怎么答
       - 原地（连着两步没意外）→ 说清卡在哪
       - 步数用完 → 说清停在哪、下一步是什么
       - 完了 → 凭什么算完
```

小林看到的不是一条更长的回答，是一串"我以为会看到 A → 实际看到 B → 所以我改去看 C"。被放下的候选折起来，想看再点开。

拿今天那一下当例子，这个循环里的它会是这样：

- 位置：要决定预测判断循环在什么时候跑。
- 候选：(a) 只在提方案时跑；(b) 先数一数标本里纠正都发生在什么时候。
- 选 (b)。预测：一大半发生在提下一步时。
- 另一个模型：你这是在找支持 (a) 的证据，把"提方案"的定义先写死再数，不然你会往宽里数。
- 做：数了。
- 对：没中。8/20，不到一半；剩下 12 条多是回答时没读、没找。
- 接着：理解变了，问题不在"提方案"这个时刻，在"想一件事"的全过程，窄比我以为的多。下一步去看那 12 条里，agent 当时手上本来有什么材料没去读。

这一串，比十轮里任何一轮都更像"想得不一样"，因为中间有一次被事情本身打了脸。

还有一件要说清：**这个循环第一次真跑，对象不能是 Cognos 自己。** 要是一件外面的事，结果由事情本身给，不由小林给，也不由检查给。候选在第八节。

## 六、设计方案（交给 agent）

### 6.0 先读、先查的

- 读：本文件，`/mnt/project-files/纠正标本/预测判断十轮-2026-11-09.md`，`/mnt/project-files/纠正标本/AI漏在哪-2026-11-09.md`，`docs/` 里 10/27 的"为什么会停"（项目文件 `框架审视/为什么会停-2026-10-27.md`），`lib/Service/ContinuationService.php` 文件头的说明。
- 底子：在 PR #61 的分支 `claude/project-thread-i8lmw3` 上做（要用到纠正）。它的底是 #54 的分支。
- **动手前先查清一件事**：ContinuationService（hang / start / afterRun / resume）现在对 Norm 空间的对话能不能用。Norm 空间的对话是 `NormService::spaceConversation()` 给出的创立空间对话；`NormService::agentLines()` 里目前没有提 hang_open / stop_here。查清是"直接能用"、"改一两处能用"，还是"不能用"。能用就复用；不能用，先停下报告，不要另造一套接着走的机制。
- 8780 上部署照老规矩：PC 工作区不 commit、不 stash、不 checkout，覆盖前先备份，用 `git --no-optional-locks`，改了 TOOLS 要重启桥，桥只能有一个，重启前看 `/health` 是不是 busy。

### 6.1 存什么（不加表）

都存在 `cognos_norm_events` 里，正文和 JSON options，和纠正一样，不进 `events()`（「正在发生」里不出现）。

**kind = `advance`**（一次推进）

| 字段 | 说明 |
|---|---|
| text | 这件事是什么，一句话 |
| options.open_id | 挂着的那件没完的 #id（复用 hang_open） |
| options.budget | 这次最多几步，默认 6，最多 12 |
| options.started_at / stopped_at | 时间 |
| options.stop | `{act: 接着/卡住/完了/原地/步数完, why}` |
| options.ask | 只有小林能定的：`{question, own_answer, guess}`，可空 |
| options.who | 谁在推进（Claude / Codex） |

**kind = `step`**（一步）

| 字段 | 说明 |
|---|---|
| text | 位置：现在对这件事的理解 |
| options.advance_id | 属于哪次推进 |
| options.n | 第几步 |
| options.candidates | `[{text, outward: bool}]`，至少两个 |
| options.chosen | 选了哪个（下标） |
| options.why | 为什么选它 |
| options.prediction | 做了会看到什么 |
| options.judge | `{who, says, check, bigger, ok: bool}`；裁判没跑成时 `{who: "none", why}` |
| options.took_judge | agent 听没听裁判、为什么（一句） |
| options.did | 实际做了什么（工具名 + 对象，例：读 盈利循环-1103.md；搜 "CNC 学徒 深圳 晋升"） |
| options.outward | 这一步实际有没有往外（读了材料、搜了、跑了、写了样子、算了） |
| options.result | 看到了什么（摘要，≤2400 字） |
| options.hit | `中` / `没中` / `意外` / `查不了` |
| options.changed | 理解变了什么；没变写"没变" |

### 6.2 agent 用的工具（MCP，`tools/cognos-space-mcp/server.py`）

1. **`advance_begin`**(space_id, space_type, norm_space, about, budget?)：
   开一次推进。服务端：没有对应的挂着的就 `hang`，建 `advance`，返回 advance_id 和预算。
2. **`step_plan`**(advance_id, position, candidates[], chosen, why, prediction)：
   - 服务端检查：上一步有没有 `step_result`，没有就 422（"先说上一步看到了什么"）；候选少于 2 个，或没有一个 outward，就 422；预测是空的，或者只有"有用""有价值"这类不能被打脸的话（长度太短也算），就 422，并提示"写到能被结果打脸"。
   - 步数到了预算，返回"步数用完，用 stop_here 停下"。
   - 通过以后调裁判（6.3），把裁判的话原样返回给 agent。
3. **`step_result`**(step_id, did, outward, result, hit, changed, took_judge)：
   记下这一步做了什么、看到什么。服务端做原地判断（6.4），原地就在返回里说"连着两步没意外，换一类步子，或者停下"。
4. 停下仍用已有的 **`stop_here`**，加一个可选参数 `ask {question, own_answer, guess}`，`act` 里多 `原地`。afterRun 照旧决定接不接着叫。

`claude_bridge.py` 的 TOOLS 白名单加上这三个。

### 6.3 裁判

- 桥上新开 `POST /judge`：收 `{space_type, space_id, step}`，用已经接好的 `codex exec`（只读，跑的是小林 ChatGPT 的额度，不吃 Claude），时限 120 秒。Codex 没配好或者超时，返回 `{who: "none", why}`，**推进不因此停**。
- NormApiController 里 `step_plan` 的路由去调它（走 `ClaudeBridgeService`），把结果写进 step 的 `options.judge`。
- 给裁判的输入：这一步的位置、候选、选择、预测；空间自述里"怎样算往前走"和"怎样算在原地"；这个空间最近 3 条纠正（原话 + 漏在哪）；收和窄的定义（`NormService::PULLS`）；前面几步的 `changed`。
- 裁判的提示词（照这个意思写，不要写成让它"展示思考过程"）：

  > 你在看另一个 AI 想一件事时的一步。不要评价它好不好，回答三件事，每件一两句：
  > 1. 这一步会不会是"收"（换成好做的题、只走一小步、跳到结论）或者"窄"（只在手上已有的话里转、不去读材料、不往外找）？是哪一种，凭什么。
  > 2. 它的预测，要去查什么、看什么，才能证明它错了？说一个具体的动作。
  > 3. 有没有比这一步更大的、更直接碰到这件事本身的一步？有就说，没有就说没有。
  > 这些问题可以帮你看：这一步有什么用？做完会怎样？和普通 AI 的做法有什么区别？根本目的是什么？就这么点吗？
  > 只回 JSON：{"pull": "收|窄|都不是", "says": "...", "check": "...", "bigger": "...或空", "ok": true|false}

- `ok` 只是裁判的看法，不拦 agent。agent 不照做，要在 `took_judge` 里说为什么。

### 6.4 原地、停下、接着

- **原地**：连着两步 `hit` 是"中"、`changed` 是"没变"；或者连着两步 `outward` 是 false。这时 `step_result` 的返回提醒它换一类步子；第三步还是这样，服务端记 `stop.act = 原地`，等同于 stop_here 的原地，afterRun 不再接着叫。
- **步数完**：到预算就停，留下停在哪、下一步是什么，act 是"接着"。afterRun 照 ContinuationService 原来的每日上限决定要不要接着叫。
- **卡住**：只有小林能给的，填 `ask`。
- 和 ContinuationService 已有的"口子和以前几乎一样就原地"并存，不替换。

### 6.5 agent 进来时读到什么（`NormService::agentLines`）

在纠正那几行后面，加一段推进的说明，只在这次运行是推进的时候加（推进由 `advance_begin` 开，或者由「推进」按钮开，见 6.6）。意思是：

- 你这次是在推进一件事，不是回答一句话。先读这个主体的历史、总观、自述、纠正，再动手。
- 每一步用 `step_plan` 写位置、两个以上不同种类的候选（至少一个往外）、预测；读裁判的话；真去做；用 `step_result` 写看到什么、中没中、理解变了什么。
- 预测写"会看到什么"，不要写"会有用"。
- 下一步从"变了什么"里来。没变，就换一类。
- 遇到只有小林能定的，停下，留下问题、你自己的答案、你猜他怎么答。
- 不要为了步数凑步子，不要在回答里写一段"我想过 A、B"；步子都在推进里，回答里只说结果和停在哪。

### 6.6 界面

- **Norm 空间对话框旁边加「推进」按钮**：点了弹一个小框，填"推进什么"（默认是总观里第一条开着的线，可以改，可以直接写一句话），步数（默认 6）。点开始，走 `POST /norm/{id}/advance`，后端建 advance、挂着、叫 agent（模式同现在的对话，带 6.5 那段）。
- **空间页加一页「推进」**（`js/norm-project.js` 的 view 里加 `['advance','推进']`），每次推进一块：
  - 头：推进什么、几步、停在哪、为什么停；有 `ask` 的，把问题放最上面，下面是它自己的答案。它猜你怎么答，默认折起来（不要让你先看到它的猜测）。
  - 每一步一行链条：**以为会看到** → **裁判说** → **做了** → **看到** → 中 / 没中 / 意外 → **理解变成**。没中和意外的那一步要显眼。
  - 没选的候选、裁判的完整原话折起来。
  - 手机宽度 390px 能看。
- 对话里推进结束时，agent 的回答只写结果和停在哪，带一个链接到「推进」页的这一次。

## 八、怎么算做成了

不是"能跑通"，是这几样：

1. 一次推进里，至少有一步因为"看到的和预测的不一样"，后面换了方向。这在链条上看得见。
2. 至少一半的步子是往外的（读了材料、搜了、跑了、写了样子、算了）。
3. 小林看了并排对照，不说"有什么用""就这么点吗"。说了，就按纠正记下，这次推进算没做成，下一次看是收还是窄。
4. 没中的那一步被记下来，不被抹平。
5. 花费：一次推进 6 步，大约是一次长一点的 Claude 运行，加 6 次 Codex。超出要在第一次跑完后报出来。

## 九、我自己还没把握的

- 往外的那一步，Claude 在桥里现在能做到哪些：读空间、读 Nextcloud 里的笔记、在工作目录跑命令。能不能联网搜，要看桥里 Claude Code 的权限设置，6.0 时一起查清。不能搜，"往外"就只剩读材料和跑东西，第一次真跑最好挑小说或盈利循环里已有材料多的那条。
- GPT 当裁判，会不会也有自己的收，把大胆的一步判成"做不到"。所以裁判只说"去查什么"，不拦。
- 第 6.1 里"预测能不能被打脸"，服务端只能挡住最明显的空话，挡不住写得漂亮的空话。真正挡住它的，是下一步必须写 `result` 和 `hit`：空话的预测，到结果那里会写不出"中"还是"没中"。要在第一次真跑后看 `查不了` 占多少。
