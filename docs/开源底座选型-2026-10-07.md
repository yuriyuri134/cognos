# 开源底座选型与试用门槛

用户已选择自部署开源底座，在上面扩展 Cognos。下列能力来自官方资料，尚不等于本机完整旅程验收。

| 候选 | 已核实能力与版本边界 | 对当前目标的判断 |
| --- | --- | --- |
| Nextcloud Hub | Files / Talk / Office；Deck 任务看板；开放 API 与应用扩展；Deck App Store 声明支持至 Nextcloud 35 | 优先隔离试用。基础组件较齐，仍必须实测“一个项目里找得到讨论、材料、任务、决定”，不能靠应用图标数量通过 |
| Huly / Platform Collective | Chat / Project Management / 文档；EPL-2.0；原 hcengineering/platform 声明冻结、官方托管关闭，后续开发转 Platform-Collective/platform | 功能形态更接近项目中心，保留对照。社区组织仍标记 forming，维护与升级能力不能按旧品牌声誉推断 |
| Zulip | topic 组织异步讨论；自部署；Bot/webhook 接入 | 讨论强，但不能单独承载完整文件/任务/文档旅程；避免第一版变成多个系统拼接 |
| Plane Community | AGPL-3.0，官方说明功能对齐 Cloud Free；Wiki 官方页标记 Pro | 可作任务底座；不将官网全功能误判为开源版现成能力，组织聊天仍需补足 |
| Twake | 当前 Workplace 官网包含 Chat/Drive/Mail 等；旧 TwakeApp/Twake 跳转 linagora/twake-legacy | 不直接 fork 旧仓库；新套件的一体化与部署兼容需另验 |
| 飞书 | 官方提供自建应用、机器人、云文档集成 | 托管替代路线可行，但用户本轮已选自部署开源，暂不作为实施底座 |

## 决策：先试 Nextcloud，再决定正式底座

独立 compose project、独立 volumes、只监听本机 8780。试用部署不挂载旧 Vault、org.db 或 runtime 状态，不迁移旧原文。正式环境可考虑官方 AIO；本次采用可复现的小型 compose 为扩展/API/旅程试用，不把试用 compose 当成全部 Hub 组件已经部署。

第一轮：两独立成员创建/指派任务、另成员查看/修改、文件共享下载、项目讨论引用；重启后持续、非成员拒绝、中文和手机操作。随后邀请、项目概况、决定与文件关联、搜索、次日继续。若仅能在多 App 之间跳转而无法连续协作，应比较 Huly 社区版或做小型项目聚合扩展；不立刻大 fork。

## Cognos 的扩展边界

身份/成员权限/共享文件/基础任务交给底座；Cognos 承载特有的讨论来路、决定关联、AI 参与、活动及执行回流。优先官方 API/应用插件，不改底座核心；外部对象保留原 ID、权限与版本，不默认复制成另一套权威状态。导入旧资料分阶段进行，绝不回写第一发生场。

## 当前本机事实

Docker CLI 已安装（29.2.1）。用户已手动启动引擎，当前沙箱访问 default/desktop-linux pipe 返回 permission denied，权限工具无法表示 named-pipe 路径；因此启动交给普通 Windows PowerShell 的统一入口。首次用户粘贴丢引号而未执行脚本，已改用 `powershell -NoProfile -ExecutionPolicy Bypass -File ...\run-trial.ps1` 单行入口。部署配置与 Windows PowerShell 5.1 准备步骤通过，三镜像 Registry manifest HTTP 200 并固定 digest；尚未取得运行成功/旅程验收证据。
