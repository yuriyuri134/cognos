# 独立实验版：代码候选与隔离数据

本入口用于把一份修改后的 Cognos 代码放到 **另一套可登录、可检查的 Nextcloud** 里。原版 8780 的代码、数据库、文件、队列和桥都不与它共用。实验副本在验证前后始终保持 restore quarantine（禁止主动派发 AI、关闭 cron 和宿主桥）；这不是一个已经接通完整 Agent 能力的正式第二实例。

## 一、代码必须从另一份目录来

当前仓库的 deploy/nextcloud-trial/cognos-app 直接绑定生产 8780。**不要在原工作目录切换到实验分支**，否则即使没提交，8780 的应用代码也会改变。

在另一目录单独克隆实验分支，例如在 PowerShell 中：

    git clone --branch gpt/experimental-cognos-integrated-20261109 --single-branch https://github.com/yuriyuri134/cognos.git C:\cognos-experimental

以下候选代码路径是：

    C:\cognos-experimental\deploy\nextcloud-trial\cognos-app

## 二、从一次验证通过的备份启动实验副本

先从**原版工作树**按现有备份流程制作完整备份：备份脚本要读取原版的 Cognos 应用、私有凭据和桥状态，所以不要在实验克隆里执行 `backup`。备份需包含数据库、完整文件卷、Cognos 应用与对应镜像。备份会短暂停止原版写入，必须先确认桥空闲；绝不能直接复制正在写入的数据库。

然后在实验克隆中校验并恢复这份备份。把下面两个路径改成你电脑上的真实路径：

    $Backup = 'C:\path\to\original\deploy\nextcloud-trial\.backups\backup-完整备份目录'
    $OriginalApp = 'C:\path\to\original\deploy\nextcloud-trial\cognos-app'
    $CandidateRoot = 'C:\cognos-experimental\deploy\nextcloud-trial'
    $CandidateApp = Join-Path $CandidateRoot 'cognos-app'

    Set-Location $CandidateRoot
    python .\backup_restore.py verify $Backup
    python .\backup_restore.py drill $Backup --port 8781 --candidate-app $CandidateApp --production-app $OriginalApp

完成后在本机打开 http://127.0.0.1:8781 ，登录备份内的独立副本账号进行检查（密码仍属备份中的私有材料）。副本中的修改不会写回原数据库。

流程先恢复原备份并核对结构及文件，再在独立文件卷里替换 Cognos 应用，检查 PHP 语法、执行副本自己的 occ upgrade，最后核实隔离仍有效，才开放 8781。候选版本必须不低于备份版本，且脚本拒绝使用原版正在挂载的应用目录。任何错误都不会自动解除隔离或推进到正式版；失败的演练容器、卷和记录须按 state.json 核对后处理。

## 三、这还不能证明什么

- 本工具不会合并 GitHub 分支、更新 master、覆盖原版 8780 或自动开启一个公开网址。
- 隔离副本有原版数据的副本，但 AI 主动调用和宿主桥被禁止，因此适合查看 UI、历史、人工互动与数据库迁移，不适合在这里声称完整 Agent 工作流已通过。
- 目前代码只做了无 Docker 的单元检查；真正的镜像恢复、Nextcloud 升级、登入和手机宽度检查还要在有 Docker 的电脑上逐项运行。
- 要让实验版长期独立运行、可调用 Agent，必须另外设计独立桥身份、密钥、队列和出站权限，在确认不会回写正式系统后再开放；不能直接关闭 quarantine。
- 需要交付正式版时另开部署决定：先比较两个版本，核对数据迁移与回退路径，再由人决定合并/部署。这里不提供自动推广命令。
