# Nextcloud 试用环境备份与隔离恢复

适用于当前 Windows 本机部署。备份保存在 `deploy/nextcloud-trial/.backups/` 下的私有目录，包含账号资料、配置和原始内容。运行时使用的独立 AI 客户端应先停止写入。桥有正在做的工作时，工具会拒绝开始备份。

## 创建和验证备份

`--bridge-pid` 填入本机空闲 Claude 桥的进程号。按该桥当前配置传入 `--bridge-no-commands` 和 `--bridge-no-self-merge`。桥已停止时省略进程号。

```powershell
python deploy/nextcloud-trial/backup_restore.py backup --bridge-pid <pid> --bridge-no-commands --bridge-no-self-merge
python deploy/nextcloud-trial/backup_restore.py verify <backup-directory>
```

工具暂时关闭写入并停止应用和定时任务，冻结空闲桥后配套归档数据库、数据库全局角色与授权、Nextcloud 文件树、实际挂载的 Cognos 应用以及宿主侧状态。它恢复生产服务后再保存固定镜像。`COMPLETE` 和清单齐备才可验收，验证会重新计算每个归档的大小和 SHA-256。

备份包含 Nextcloud 的原始文件、配置、已安装应用和主题。独立归档保存实际导入挂载、桥工作目录、运行日志、待发送及未确认记录，以及清单列出的 MCP 回执状态。默认路径随当前环境变量解析，其他宿主路径需要在备份前核对。Redis 在演练中从新缓存启动。外部模型的全局登录信息和临时隧道状态留在各自系统。

## 启动隔离副本

```powershell
python deploy/nextcloud-trial/backup_restore.py drill <backup-directory> --port 8781
```

工具从空数据库、独立文件卷和固定镜像恢复。启动前比对文件内容、目录和链接、属主及权限，操作日志和隔离覆盖配置单独处理。恢复原数据库角色和授权后，比对数据库记录、结构与账号权限相关表。恢复副本开启 `cognos_restore_quarantine`，保留备份当时的租约和队列。当前回执仍可按原编号交回，后台接续和外部 AI 调用暂停。

应用只加入内部网络。Docker Desktop 上由独立的固定目标代理发布 `127.0.0.1:8781`，只有代理连接宿主入口。使用独立浏览器配置打开副本，登录后可看到隔离提示。原文件与宿主状态归档可以单独取出，演练启动时保持桥、定时任务和隧道关闭。

工具打印副本容器与运行记录路径。演练结束可按该记录停止同一组入口、应用、数据库和缓存容器，副本卷会保留。正式恢复和解除隔离需要核对外部动作和客户端同步。使用过时备份时，按 Nextcloud 说明评估是否执行 `maintenance:data-fingerprint`。参考 [Nextcloud 备份说明](https://docs.nextcloud.com/server/stable/admin_manual/maintenance/backup.html)、[恢复说明](https://docs.nextcloud.com/server/stable/admin_manual/maintenance/restore.html) 和 [PostgreSQL 转储说明](https://www.postgresql.org/docs/17/app-pgdump.html)。

## 2026-11-05 演练

在 Cognos 0.34.1 上恢复了约 2.83 GB 的归档。60 张表和 42,406 个文件树条目比对通过，两个原数据库角色的指纹一致。首次恢复发现安装时生成的数据库账号也必须归档。修正版加入全局角色和对象授权，配套重新备份后通过。Docker Desktop 的内部网络未发布宿主端口，固定目标代理补齐了本机入口。启用入口后，从应用容器访问宿主桥、Hermes 和测试外网地址仍被拦截。

登录页面实际回查了旧版本和来源、采用和复核、尝试阶段、Claude 与 Codex 的原回执。390px 页面通过，截图已检查。待发送样本由工程脚本生成。通过真实 HTTP 模拟回执丢失并重试，同一编号只生成一条消息及一份回执，后续工作仍待处理，未确认运行与备份原件保持原状。检查脚本为 `check_backup_state.php`、`check_backup_files.php`、`check_restore_guard.php`、`check_restore_visible.cjs` 和 `check_restore_delivery.py`。
